<center><h1>Запуск эффектов</h1></center>

*Запустите эффект командой, скриптом или с кости модели и управляйте им, пока он идёт.*

Примеры Kotlin ниже - фрагменты серверного `.node.kts`. `entity` - сущность, к которой привязывается эффект, `player` - серверный игрок, `level` - его мир (`player.serverLevel()`). Сначала создайте `.vfx` по инструкции во [введении](/docs/hollowengine/vfx).

## Имена эффектов

Имя эффекта - идентификатор ресурса. `project:vfx/sparks.vfx` - это файл `hollowengine/assets/project/vfx/sparks.vfx`; сокращённые формы `project:sparks` и `project:vfx/sparks` означают то же самое. Эффекты из аддонов и ресурспаков используют своё пространство имён. Команда подсказывает все загруженные эффекты.

Если эффект не запускается, проверьте имя, перезагрузите клиентские ресурсы через `F3 + T` и посмотрите в консоли IDE сообщение о файле, который не удалось разобрать.

## Команды

Команда `/he vfx` принимает позицию или сущность и имя эффекта:

```mcfunction
/he vfx ~ ~1 ~ project:sparks
/he vfx @s project:sparks
```

Позиция запускает эффект в этой точке. Сущность запускает его на сущности, и он следует за ней, пока она жива.

## Из Kotlin

Используйте `Vfx.play(level, position, "project:sparks")` или `Vfx.play(entity, "project:sparks")`. Обе возвращают `VfxHandle`:

```kotlin
import ru.hollowhorizon.hollowengine.common.vfx.Vfx

val handle = Vfx.play(level, player.position(), "project:sparks")

handle.moveTo(player.position().add(0.0, 2.0, 0.0))   // только для эффектов в точке
handle.stop()                                          // перестать испускать, дать частицам дожить
handle.stop(immediate = true)                          // убрать всё сразу
```

Эффекты, привязанные к сущности, следуют за ней сами, поэтому `moveTo` на них не действует. Эффект запускается для всех, кто его видит: для всех в измерении, если это точка, и для всех, кто отслеживает сущность, если это сущность. Игрок, начавший отслеживать сущность позже, получает эффект от `handle.update()`.

## Передача данных эффекту

Для перехода к именованному событию таймлайна вызовите `handle.jumpTo("release")`. Эффект продолжит воспроизведение с этого момента. Правила [секций](/docs/hollowengine/ide/timeline) VFX вычисляются на клиентах, где играет эффект; серверную игровую логику не стоит привязывать к тому, что клиент показал.

У каждого хэндла есть хранилище данных, которое выражения эффекта читают как `d.<name>`. Записывайте в него через `dataKey` - тот же типизированный ключ, что и для [данных NPC](/docs/hollowengine/scripting/npc/data):

```kotlin
val Charge = dataKey<Float>("charge") { 0f }

val handle = Vfx.play(entity, "project:beam")

handle[Charge] = 0.25f       // эффект видит d.charge == 0.25
handle[Charge] = 1f          // и обновляется, как только значение изменилось
```

В эффекте используйте имя из ключа: `d.charge * 4`. Значение, которое ни разу не записывали, читается как `0`. Так один эффект можно использовать для слабой и сильной версии одной атаки или управлять им из геймплея, например шкалой заряда.

## На кости модели

Эффект может быть привязкой к кости модели. Откройте модель в [редакторе рига](/docs/hollowengine/models/rig-editor), выберите кость и добавьте привязку VFX через **+ Attach**:

| Поле | Значение |
| --- | --- |
| **Effect** | Запускаемый файл `.vfx`. |
| **Offset**, **Rotation**, **Scale** | Размещение относительно кости. |
| **Start with the model** | Начинать, когда появляется модель; иначе эффект запускает скрипт. |

Эффект следует за костью, пока модель анимируется, так что это способ повесить пламя на меч или свечение на руку.

## Советы

- Держите один эффект на одну идею и комбинируйте их в скриптах, а не делайте один гигантский эффект со всеми вариантами.
- Задавайте **Предел** у эмиттеров и **Длительность** у эффекта, чтобы ничто не работало вечно по ошибке, и останавливайте долгоживущие эффекты через `handle.stop()`, когда их владельца больше нет.
- Проверьте эффект с шейдерпаком, если им пользуются игроки. Эффекты рисуются поверх финального кадра пака, но туман и погода по-прежнему принадлежат паку.
