<center><h1>Запуск и сохранение прогресса</h1></center>

## Запуск из Kotlin

В серверном `.node.kts` с [зависимостью от Narrative](/docs/hollowengine/addons/narrative) запустите историю на игроке, который должен её увидеть. Здесь `player` — это `ServerPlayer`, например игрок, который нажал на NPC.

```kotlin
player.launchStory("arrival") {
    scene("quests/arrival.story")
}
```

Путь указывается относительно `scripts/`. Для файла из пространства имён зависимости используйте `addon-id:quests/arrival.story`. По умолчанию запуск идёт с этапа `main`, который создаётся из узла **Начало**.

`launchStory` сразу возвращает объект управления запуском. Повторный вызов с теми же владельцем и ключом возвращает текущий запуск, пока тот активен. Используйте `await()`, чтобы дождаться результата, или `cancel()`, чтобы остановить выполнение. После завершения историю можно запустить снова.

## Владельцы и участники

Владелец определяет, где хранится прогресс и когда история может выполняться. Серверная история сохраняется с миром, история сущности — с сущностью, история ноды — с запущенной нодой. История игрока может дождаться его возвращения.

Участники определяют, кто видит сцену. История, принадлежащая игроку, по умолчанию показывается ему. Для сервера, NPC или другого владельца, который не является игроком, укажите участников явно.

```kotlin
npc.launchStory("arrival-${player.uuid}") {
    scene("quests/arrival.story", with = listOf(player))
}
```

Здесь у каждого взаимодействующего игрока свой ключ. Передайте несколько игроков в списке, чтобы показать им общую сцену. Общую реплику может продвинуть любой участник. В опросе побеждает вариант с наибольшим числом голосов после того, как проголосуют все участники, оставшиеся в игре. При равенстве голосов вариант выбирается случайно.

## Контрольные точки и откат

Поставьте **Чекпоинт** перед выбором или другим важным шагом и задайте ей стабильное имя. Запуск хранит свой прогресс. Блок отката или команда `rewind` возвращает историю к контрольной точке и отменяет более поздние действия, записанные в журнал. Обычные эффекты, например сообщения в чате, сохраняются. Если последняя контрольная точка отмечена `restart = true`, при восстановлении история также возвращается к ней.

В скриптах то же поведение доступно через [возобновляемые этапы Kotlin](/docs/hollowengine/addons/narrative/kotlin). При изменении истории с сохранёнными запусками сохраняйте имена этапов и ID узлов. Перемещение узла на холсте не меняет ход выполнения.

## Команды для проверки

Оператор может посмотреть и изменить запуски истории. Владельцем в команде может быть `server`, `entity <entity>` или `node <path>` для ноды, запущенной на самом сервере.

```mcfunction
/he story entity @s start "quests/arrival.story" arrival
/he story entity @s list
/he story entity @s checkpoints arrival
/he story entity @s rewind arrival
/he story entity @s stop arrival
```

Укажите после ключа имя контрольной точки, чтобы вернуться к ней. Команда запуска с теми же владельцем и ключом заменяет текущий запуск. Сцену увидит владелец, если он игрок, иначе игрок, выполнивший команду.

Игроки могут продвинуть реплику через `/he dialogue advance` или проголосовать в последнем открытом опросе через `/he dialogue choose <n>`. Индексы команды начинаются с нуля. Первый вариант — `0`.

## Свои реплики и варианты ответа

Из Kotlin используйте `say` из пакета `narrative.speech` и `choose` из `narrative.poll`. Список игроков можно передать явно через `to`. Внутри сцены функции могут использовать её участников. События `SayEvent` и `ChoiceEvent` позволяют аддонам заменить стандартный интерфейс другим представлением, например чатом.

Чтобы изменить оформление, объявите [UI-оверлей](/docs/hollowengine/scripting/ui/ui-files) с ID `hollowengine-narrative:speech` или `hollowengine-narrative:choice`. Импортируйте `SpeechUiKeys` из пакета `speech` или `ChoiceUiKeys` из `poll`, чтобы читать данные сессии и отправлять события продолжения реплики или голосования.
