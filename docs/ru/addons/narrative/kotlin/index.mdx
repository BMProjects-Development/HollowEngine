<center><h1>Возобновляемые этапы истории</h1></center>

Используйте этап Kotlin для последовательности, которая должна продолжиться после повторного открытия мира. Установите компилятор и добавьте [зависимость от Narrative](/docs/hollowengine/addons/narrative). Обычные [обработчики нод](/docs/hollowengine/scripting/node) доступны в самом движке.

## Объявление и запуск этапа

Пометьте suspend-функцию верхнего уровня аннотацией `@State`. Имя функции станет именем этапа, если не указать другое в самой аннотации.

Сохраните пример в `hollowengine/scripts/examples/arrival.node.kts` и выполните `/he scripting run "examples/arrival.node.kts" main`.

```kotlin
@State
suspend fun main() {
    println("Ждём прибытия")
    checkpoint("arrival")
    wait(100, "before-bell")
    announce()
}

@State
suspend fun announce() {
    println("Прибытие завершено")
}
```

Запуск ноды с именем начального этапа создаёт запуск истории с ключом `main`. Привяжите ноду к сущности с начальным этапом командой `/he scripting attach <entity> <path> <stage>` или вызовите `launchStory("key") { ... }` из обработчика. Запуск также может принадлежать серверу или сущности.

## Вызовы и контрольные точки

Вызов другого этапа работает как вложенный вызов. Когда вложенная функция заканчиваются, внешняя продолжается. Запуск сохраняет стек вызовов, аргументы и локальные переменные, которые понадобятся после возобновления. Эти значения должны быть сериализуемы. Сущности сохраняются как ссылки, и история будет ждать, пока чанки с сущностью загрузятся или игрок из переменной зайдёт на сервер.

Контрольная точка отмечает место возобновления и цель для отката. Вызывайте `checkpoint("name")` в самом этапе и используйте разные имена в пределах этапа. Работа после последней сохранённой границы может повториться после перезапуска. Если изменение мира нужно воспроизводить или отменять, используйте действие с журналом. Подробнее в статье [Собственные блоки истории](/docs/hollowengine/addons/narrative/stories/custom-blocks).

## Сохранение прогресса

| API                       | Что сохраняет                                                                                              |
|---------------------------|------------------------------------------------------------------------------------------------------------|
| `var trust by saved(0)`   | Объявляется на уровне скрипта. У каждого запуска своё значение, общее для его веток.                       |
| `segmentTag()`            | NBT текущего отрезка между границами чекпоинтов или действий. Следующий отрезок начинается с пустого тега. |
| `once("key") { ... }`     | Пропускает уже выполненный блок при повторе отрезка, в том числе после отката.                             |
| `remember("key") { ... }` | Возвращает первый сохранённый результат при повторе отрезка. Результат должен сериализоваться.             |
| `forget("key")`           | Удаляет записи `once` и `remember` для ключа в текущем отрезке.                                            |

Для повторов внутри цикла используйте разные ключи, например `"reward-$index"`. Данные о самой ноде или сущности лучше храните в [сохранении ноды](/docs/hollowengine/scripting/node) или [данных сущности](/docs/hollowengine/scripting/npc/data).

## Ожидание между перезапусками

- `wait(100, "gate")` ждёт 100 игровых тиков. Время, пока сервер выключен, не учитывается.
- `wait(5.sec, "gate")` использует срок по реальному времени. Время, **пока сервер выключен, учитывается**.
- `wait(instant, "gate")` ждёт до указанного `java.time.Instant`.

Каждый из этих вызовов запоминает срок на время ожидания. Давайте уникальное имя каждому ожиданию в одном отрезке. Чтобы запустить несколько веток истории параллельно, используйте [асинхронные действия](/docs/hollowengine/addons/narrative/kotlin/async).
