## Дочерние стейты и `async`

Иногда нужно запустить параллельную логику: например, NPC идёт к точке, пока игрок читает диалог, или на фоне проигрывается анимация.
Для этого можно использовать `async` внутри активного стейта.

```kotlin
@State
suspend fun main() {
    async("ambient_animation") {
        while (true) {
            println("NPC осматривается")
            wait(3.sec)
        }
    }

    println("Основной диалог продолжается")
    wait(5.sec)
    nextScene()
}

@State
suspend fun nextScene() {
    println("Переходим к следующей сцене")
}
```

Дочерний стейт получает собственный `stateTag()` и сохраняется отдельно от родительского стейта. Когда родительский стейт завершается или переходит дальше, его активные дочерние задачи отменяются.

Для долгоживущих фоновых процессов лучше использовать понятные имена (`"ambient_animation"`, `"move_to_gate"`, `"wait_for_player"`), потому что имя становится ключом дочернего контекста при сохранении.
