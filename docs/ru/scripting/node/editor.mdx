<center><h1>Свойства в редакторе</h1></center>

*Добавляем параметры node-скрипту прямо в редакторе сущностей.*

## Зачем

Ноде, прикреплённой к сущности, часто нужны одно-два значения, принадлежащие именно этой сущности: какой диалог запускает этот НПС, как далеко патрулирует стражник, ограничен ли товар у торговца.
Захардкодить их - значит держать по копии скрипта на каждого НПС. `editor` позволяет объявить их один раз и передать редактирование в редактор сущностей, где их легко менять не лезя в код.

Каждое значение принадлежит одному скрипту: две сущности с одним и тем же скриптом хранят свои собственные значения, они сохраняются вместе с сущностью и восстанавливаются вместе с ней.

```kotlin
@file:Attach(ru.hollowhorizon.hollowengine.common.entities.NpcEntity::class)

editor.name("Диалог при взаимодействии")
editor.description("Запускает диалог для игрока, который взаимодействовал с этой сущностью.")
editor.icon("hollowengine:textures/gui/dialogues/simple.png")

val dialogue by editor.property<String>("Путь к диалогу", assets = ["story"]) { "stories/example.story" }

onInteract { event ->
    DialogueController(dialogue).start(event.player as ServerPlayer)
}
```

Откройте редактор сущностей, перейдите на вкладку **Скрипты** - прикреплённый скрипт покажется под этим именем, с полем на каждое свойство.

![Свойства скрипта в редакторе сущностей](/hollowengine/pictures/npc/scripts-tab.webp)

## Имя скрипта

- `editor.name(...)` - как редактор называет скрипт вместо имени файла.
- `editor.description(...)` - строка под его заголовком.
- `editor.icon(...)` - иконка `namespace:textures/...` рядом с ним.

Все три - ключи перевода, если такой ключ есть в языковом файле, и обычный текст, если нет.
Так скрипт может сразу нести читаемый текст, а перевод добавится позже, без правок кода:

```kotlin
editor.name("mypack.script.guard.name")
```

```json
{
  "mypack.script.guard.name": "Поведение стражника"
}
```

## `editor.property(...)`

```kotlin
val radius by editor.property<Int>("Радиус патруля", min = 1.0, max = 32.0, slider = true) { 8 }
val greeting by editor.property<String>("Приветствие", multiline = true) { "Здравствуй, путник!" }
val hostile by editor.property<Boolean>("Нападает без предупреждения") { false }
```

Значение хранится под **именем самого свойства в Kotlin** (`radius`, `greeting`), а не под подписью, поэтому если название в строке изменить на перевод или переименовать его, то сохранённое значение не пропадёт; а вот переименование самой переменной сбросит его до значения по умолчанию.

Делегат каждый раз читает текущее значение, поэтому обработчик, написанный через него, всегда видит то, что редактор выставил последним:

```kotlin
val greeting by editor.property<String>("Приветствие") { "Привет!" }

onInteract { event ->
    event.player.sendToast(greeting.literal) // Всегда то значение, которое сейчас показывает редактор
}
```

### Типы значений

Любой сериализуемый и non-null тип - то же правило, что и у [`persisted`](/docs/hollowengine/scripting/node): примитивы, строки, enum'ы, списки, словари и ваши классы с `@Serializable`.
Каждый получает подходящий редактор - галочку, числовое поле, набор кнопок для enum, список с добавлением и удалением, сворачиваемую карточку для класса:

```kotlin
@Serializable
data class Reward(
    @EditorName("Предмет") val item: String = "minecraft:bread",
    @EditorRange("1", "64") val count: Int = 1,
)

val rewards by editor.property<List<Reward>>("Награды за квест") { emptyList() }
```

Аннотации `@Editor...` у класса переносятся на его поля в редакторе ровно так же, как у компонента.
Поле такого класса может быть nullable - рядом с ним появится галочка, включающая и выключающая значение; само свойство - нет, ровно как у `persisted`.

### Параметры

| Параметр                 | Что делает                                                                                 |
|--------------------------|--------------------------------------------------------------------------------------------|
| `name`                   | Подпись. Если не указана - берётся имя свойства, приведённое к читаемому виду.               |
| `description`            | Строка под полем.                                                                           |
| `icon`                   | Иконка рядом с полем.                                                                       |
| `min`, `max`             | Границы для числа.                                                                          |
| `slider`                 | Рисует ограниченное число ползунком.                                                        |
| `multiline`              | Даёт строке больше одной строки.                                                            |
| `assets`                 | Расширения файлов, на которые указывает значение - поле превращается в выбор из того, что есть в паке. |
| `restart`                | Запускает скрипт заново после изменения значения (см. ниже).                                 |
| `onChange`               | Передаёт новое значение в блок сразу после того, как оно выставлено.                         |

### Ассеты

`assets` перечисляет добавляет иконку папки около строки, добавляя туда все файлы этого типа:

```kotlin
val model by editor.property<String>("Модель", assets = listOf("gltf", "glb")) { "models/npc.gltf" }
val script by editor.property<String>("Вложенная нода", assets = listOf("node.kts")) { "" }
```

### Реакция на изменение

Значение, прочитанное один раз при запуске скрипта - например, чтобы собрать объект - само не обновит этот объект.
Для этого есть `restart` и `onChange`:

```kotlin
// После изменения скрипт выполняется заново, поэтому `controller` пересоздаётся
val dialogue by editor.property<String>("Диалог", restart = true) { "stories/hello.story" }
val controller = DialogueController(dialogue) // без restart этот объект сам не пересобирётся.

// Или оставить ноду работать и отреагировать вручную
val radius by editor.property<Double>("Радиус", onChange = { rebuildPatrol(it) }) { 8.0 }
```

Перезапуск сохраняет всё, что у ноды было записано - `persisted`-значения, значения редактора, текущий стейт - и стартует уже с них, ровно как при перезагрузке мира.

:::advice
Значения редактора хранятся отдельно от [`persisted`](/docs/hollowengine/scripting/node), поэтому одно и то же имя можно спокойно использовать в обоих.
:::

## Что видно в редакторе

Имя и свойства скрипта читаются с работающей ноды, поэтому появляются после того, как скрипт прикреплён к сущности.
До этого в списке для прикрепления виден только путь к файлу.

Скрипты без свойств по-прежнему показываются на вкладке **Скрипты** обычной строкой - `editor` необязателен, и нода, которая ничего не объявляет, ведёт себя ровно как раньше.
