<center><h1>Введение в startup-скрипты</h1></center>

*Добавляем в игру свои предметы, блоки и всё, что Minecraft принимает только при загрузке.*

![Startup-скрипт в IDE](/hollowengine/pictures/startup/startup-script.webp)

## Что такое startup-скрипт?

Startup-скрипт - это файл с постфиксом `.startup.kts`. Он выполняется **один раз при запуске игры**, ещё до главного меню, пока Minecraft принимает регистрацию нового содержимого. Позже добавить предмет или блок уже нельзя, поэтому всё такое содержимое живёт здесь:

- предметы и блоки;
- вкладки творческого режима;
- события, которые срабатывают только при запуске: клавиши управления, рендереры сущностей, частицы, атрибуты сущностей.

Для игровой логики, которую хочется править без перезапуска, используйте [перезагружаемые скрипты](/docs/hollowengine/scripting/reload).

:::warning
Изменения в startup-скрипте применяются только после **перезапуска игры**. `/reload` и `F3 + T` его не перезапускают.
:::

## Где он выполняется

Startup-скрипт выполняется и на клиенте, и на выделенном сервере. Это важно: предметы и блоки должны быть зарегистрированы одинаково на обеих сторонах, иначе сервер не пустит игрока. Поэтому startup-скрипты с содержимым должны лежать и у игроков, и на сервере.

Если части кода нужна только одна сторона, проверьте переменную `isClientSide`:

```kotlin
if (isClientSide) {
    println("Игра запущена на клиенте")
}
```

:::warning
Выделенный сервер компилирует startup-скрипты без клиентских классов Minecraft. Если скрипт обращается к клиентскому коду (например, к `KeyMapping` или рендерерам), на сервере он не скомпилируется целиком, даже если этот код стоит внутри `if (isClientSide)`. Такие регистрации выносите в отдельный startup-скрипт, который не кладётся на сервер.
:::

## Пространство имён

Всё, что регистрирует скрипт, получает идентификатор вида `пространство:имя`. Если указать только имя, скрипт подставит пространство имён своей папки:

- для скриптов в `hollowengine/scripts` это `hollowengine-sandbox`, пока вы не зададите своё;
- для скриптов аддона - id аддона.

Своё пространство имён для папки `hollowengine` задаётся в файле `hollowengine/META-INF/plugin.properties`:

```properties
id=mypack
```

После этого `register("ruby")` создаст предмет `mypack:ruby`, а текстуры и переводы будут лежать в `hollowengine/assets/mypack/`. Можно указать и полный идентификатор: `register("othermod:ruby")`.

## События запуска

Startup-скрипт подписывается на события так же, как перезагружаемый, через `@SubscribeEvent`. Подписки живут до выхода из игры. Кроме обычных событий, здесь доступны события, которые срабатывают только при запуске:

| Событие                              | Сторона      | Для чего                                     |
|--------------------------------------|--------------|----------------------------------------------|
| `RegisterKeyBindingsEvent`           | клиент       | клавиши управления                           |
| `RegisterEntityRenderersEvent`       | клиент       | рендереры сущностей                          |
| `RegisterBlockEntityRenderersEvent`  | клиент       | рендереры блок-сущностей                     |
| `RegisterParticlesEvent`             | клиент       | провайдеры частиц                            |
| `RegisterReloadListenersEvent.Client`| клиент       | свои обработчики перезагрузки ресурсов       |
| `RegisterEntityAttributesEvent`      | обе стороны  | атрибуты своих сущностей                     |

Например, своя клавиша (этот файл - только для клиента):

```kotlin
import net.minecraft.client.KeyMapping
import org.lwjgl.glfw.GLFW

@SubscribeEvent
fun onKeys(event: RegisterKeyBindingsEvent) {
    event.registerKeyMapping(KeyMapping("key.mypack.journal", GLFW.GLFW_KEY_J, "key.categories.mypack"))
}
```

Нажатие удобно проверять в клиентском перезагружаемом скрипте:

```kotlin
@file:ClientSide

import ru.hollowhorizon.hollowengine.common.events.tick.TickEvent

@SubscribeEvent
fun onTick(event: TickEvent.Client) {
    val journal = minecraft.options.keyMappings.first { it.name == "key.mypack.journal" }
    while (journal.consumeClick()) {
        // открыть журнал
    }
}
```

## Если скрипт упал

Ошибка в startup-скрипте не мешает игре запуститься: она записывается в лог, а в игре появляется уведомление со списком упавших скриптов. Исправьте скрипт во встроенной IDE и перезапустите игру.

:::advice
Если скрипт упал до регистрации предметов, их не будет в этой сессии игры. Не открывайте в ней миры, где эти предметы уже лежат в сундуках или инвентаре: при загрузке игра может удалить неизвестные ей предметы.
:::

## Аддоны

Аддон тоже может содержать startup-скрипты. Если такой аддон включают или обновляют, когда игра уже запущена, он получает статус «требуется перезапуск» и загрузится при следующем запуске игры.
