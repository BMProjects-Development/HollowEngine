<center><h1>Обработка событий</h1></center>

*Подписываемся на события и внедряем свою логику.*

![NPC](/docs/title-missing.webp)

Система событий в HollowEngine позволяет вам внедрять собственную логику при определённых действиях в игре, включая действия игроков, сущностей, обновления блоков и т.п.

## На какой стороне срабатывает событие

В Minecraft игра делится на две стороны: **сервер** обрабатывает мир и игроков, **клиент** рисует картинку и принимает ввод. Даже в одиночной игре внутри запущен отдельный сервер. Поэтому у каждого события в этом разделе указана сторона, и слушать его нужно из подходящего скрипта:

| Сторона           | Где слушать                                                                       |
|-------------------|-----------------------------------------------------------------------------------|
| **Сервер**        | обычный `.reload.kts`                                                             |
| **Клиент**        | `.reload.kts` с `@file:ClientSide`                                                |
| **Обе стороны**   | любой из них: серверный скрипт получит серверную копию события, клиентский - клиентскую |
| **Запуск игры**   | только `.startup.kts`: событие срабатывает один раз, ещё до перезагружаемых скриптов |

Если подписаться на событие не с той стороны, движок напишет об этом ошибку в лог при запуске скрипта. Так проще заметить, почему обработчик «не срабатывает на сервере».

:::advice
Скрипты `.startup.kts` и аддоны не привязаны к стороне и получают события обеих сторон. Если такой код слушает событие «обеих сторон», проверяйте сторону сами, например через `event.player.level().isClientSide`.
:::

## Создаём обработчик

Проще всего подписаться через аннотацию `@SubscribeEvent` в [перезагружаемом скрипте](/docs/hollowengine/scripting/reload). Если обработчик нужно добавить из кода, например только при определённом условии, подпишитесь через скоуп скрипта:

```kotlin
fun onPlayerJoin(event: PlayerEvent.Join) {
    event.player.send("С возвращением!")
}

PlayerEvent.Join.subscribe(this, listener = ::onPlayerJoin)

// Вместо функции можно передать лямбду:
PlayerEvent.Join.subscribe(this) { event ->
    event.player.send("С возвращением!")
}
```

`this` здесь - сам перезагружаемый скрипт: подписка живёт, пока жив скрипт, и снимается при его перезапуске. Она учитывает сторону скрипта так же, как `@SubscribeEvent`.

:::warning
`PlayerEvent.Join.register { ... }` без скоупа подписывается навсегда, до выхода из игры. В скриптах такой обработчик не снимается при `/reload` и после каждого перезапуска будет срабатывать ещё раз.
:::

## Приоритеты

Иногда вам может потребоваться, чтобы ваше событие срабатывало раньше других (особенно если его нужно отменить).
Для этого передайте приоритет: чем он больше, тем раньше вызывается обработчик. По умолчанию приоритет нулевой.

```kotlin
@SubscribeEvent(10)
fun onPlayerJoin(event: PlayerEvent.Join) { }

// Или при подписке из кода:
PlayerEvent.Join.subscribe(this, priority = 10) { event -> }
```

## Отмена событий

Некоторые события - отменяемые, т.е. их действие можно отменить, например:

```kotlin
@SubscribeEvent
fun onBreak(event: BlockEvent.Break) {
    event.player.send("Нельзя ломать блоки!")
    event.isCanceled = true
}
```

## Ожидание событий

Иногда вам может понадобится не постоянный обработчик, а одноразовый, в особенности когда речь идёт о сюжетах, для этого есть готовый инструмент:

```kotlin
// Ждём сообщение, после чего продолжаем выполнение
val event = ServerChatEvent.await()
println(event.message.string)
```

Или с условием:

```kotlin
val event = ServerChatEvent.await { it.player.name == "..." }
```

:::warning
Это работает только внутри suspend функций!
:::
