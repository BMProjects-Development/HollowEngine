# Обычные Kotlin-скрипты

Обычный скрипт - это файл с расширением `.kts`, содержащий произвольный Kotlin-код.

Главная польза таких файлов - возможность вынести общие функции, классы и константы, а затем импортировать их в `.reload.kts`, `.node.kts` и другие скрипты. Кроме того, обычные скрипты удобно использовать для небольших одноразовых действий, экспериментов и отладки.

В отличие от специализированных типов скриптов, обычный `.kts`:

- не имеет собственного жизненного цикла;
- не получает специальный базовый класс;
- выполняется только при ручном запуске.

Для логики, которая должна автоматически реагировать на события или перезагрузку ресурсов, используйте соответствующий специализированный тип скрипта.

## Создание скрипта

Создайте в проекте новый файл с расширением `.kts`, например:

```text
scripts/
└── examples/
    └── hello.kts
```

Обычному скрипту не требуется дополнительное расширение вроде `.reload.kts` или `.node.kts`.

Открыв файл во встроенном редакторе HollowEngine, вы получите подсветку синтаксиса, диагностику ошибок и автодополнение.

## Первый скрипт

Код верхнего уровня выполняется последовательно - создавать функцию `main` не требуется:

```kotlin
println("Hello from HollowEngine!")
```

При ручном запуске движок сам компилирует содержимое файла и сразу выполняет получившийся скрипт.

В одном файле можно объявлять переменные, функции и классы так же, как в обычном Kotlin:

```kotlin
fun greeting(name: String): String {
    return "Hello, $name!"
}

class Counter {
    private var value = 0

    fun increment(): Int {
        return ++value
    }
}

val counter = Counter()

println(greeting("HollowEngine"))
println("Counter: ${counter.increment()}")
```

Переменные и объекты, созданные кодом верхнего уровня, существуют только в рамках конкретного запуска. Объявленные функции и классы при этом можно импортировать и использовать в других скриптах.

## Общая логика и импорты

Предположим, нескольким скриптам нужна одна и та же функция выдачи предмета. Вместо копирования кода вынесем её в отдельный файл:

```text
scripts/
├── common/
│   └── rewards.kts
└── quests/
    └── first_quest.node.kts
```

В `rewards.kts` объявим пакет и общую функцию:

```kotlin
import net.minecraft.world.entity.player.Player
import net.minecraft.world.item.Item
import net.minecraft.world.item.ItemStack

fun Player.reward(item: Item, count: Int = 1) {
    inventory.add(ItemStack(item, count))
}
```

Теперь функцию можно импортировать в другом скрипте:

```kotlin
@Import("../common/reward.kts")
import net.minecraft.world.item.Items

suspend fun main() {
    // Переменную игрока получите сами
    player.reward(Items.DIAMOND, 3)
}
```

Обычные `.kts`-скрипты не получают специальный набор автоматических импортов от HollowEngine. Необходимые классы следует импортировать явно:

```kotlin
import net.minecraft.resources.ResourceLocation
import net.minecraft.world.item.ItemStack
import net.minecraft.world.item.Items

val stack = ItemStack(Items.DIAMOND, 4)
val id = ResourceLocation.fromNamespaceAndPath("minecraft", "diamond")

println("$id: $stack")
```

Стандартные импорты Kotlin, такие как `kotlin.collections.*`, `kotlin.io.*` и `kotlin.math.*`, работают как обычно.

Во встроенном редакторе недостающие импорты можно определить по диагностике и предложениям автодополнения.

## Ручной запуск

Чтобы выполнить готовый скрипт, используйте команду:

```text
/hollowengine scripting run scripts/examples/hello.kts
```

Путь указывается начиная с папки `scripts`.

Выполнение происходит сверху вниз:

```kotlin
println("Step 1")

val value = 20 + 22

println("Step 2")
println("Result: $value")
```

Результат:

```text
Step 1
Step 2
Result: 42
```

Повторный запуск создаёт новый экземпляр скрипта и заново выполняет его код с первой строки.

## Ошибки компиляции

Если код содержит ошибку, скрипт не будет запущен:

```kotlin
val number: Int = "not a number"
```

В редакторе проблемный участок будет отмечен ошибкой. Счётчики ошибок и предупреждений отображаются в верхней части файла.

Нажатие на счётчик открывает подробный список всех проблем в файле.

Наиболее распространённые причины ошибок:

- отсутствующий `import`;
- неправильное имя метода или свойства;
- несовпадающие типы данных;
- обращение к API, недоступному в текущей версии Minecraft;
- использование клиентского класса на сервере;
- синтаксическая ошибка Kotlin.

## Ошибки выполнения

Код может успешно скомпилироваться, но завершиться с ошибкой уже во время выполнения:

```kotlin
val values = emptyList<String>()

println(values.first()) // У пустого списка нет первого элемента
```

В этом случае будет выброшено исключение, и оставшаяся часть скрипта не выполнится.

Для действий, которые могут завершиться неудачно, можно использовать обычную обработку исключений Kotlin:

```kotlin
runCatching {
    error("Something went wrong")
}.onFailure { exception ->
    println("Script failed: ${exception.message}")
}
```

Не рекомендуется без необходимости перехватывать все исключения и игнорировать их: это скрывает реальные ошибки в скрипте.

## Для чего использовать обычные скрипты

Типичные задачи для обычных `.kts`:

- хранить общие функции, классы и константы;
- переиспользовать логику в специализированных скриптах;
- проверить работу функции или класса;
- вывести отладочную информацию;
- создать или изменить объект;
- вручную запустить игровой процесс;
- протестировать алгоритм.

## Когда обычный `.kts` не подходит

Обычный скрипт не запускается автоматически при входе игрока, загрузке мира, тике или перезагрузке ресурсов.

Не стоит использовать бесконечные циклы:

```kotlin
// Такой код заблокирует серверный поток
while (true) {
    println("Running...")
}
```

Также обычный `.kts` не предназначен для самостоятельной регистрации долгоживущих событий. Без явного управления временем жизни обработчиков это может привести к дублированию подписок, утечкам и трудноуловимым ошибкам.

Для подобной логики используйте `.reload.kts`, `.node.kts` или другой специализированный тип скрипта.
