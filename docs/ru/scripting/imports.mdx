<center><h1>Импорты скриптов</h1></center>

*Разделяйте Kotlin-скрипты на переиспользуемые модули, а не копируйте логику между файлами.*

![Навигация по импортам скриптов в IDE](/hollowengine/pictures/ide/code-navigation.webp)

Kotlin скриптинг поддерживает импорты скриптов:

```kotlin
@file:Import("example.kts")

functionFromExample()

```

Путь считается относительно текущего скрипта. Для такой структуры:

```text
hollowengine/
└─ scripts/
   ├─ quest/intro.kts
   └─ common/dialogue.kts
```

скрипт `quest/intro.kts` импортирует `common/dialogue.kts` так:

```kotlin
@file:Import("../common/dialogue.kts")

runSomeDialogue()

```

То есть две точки означают переход на папку выше относительно текущей. Если скрипты находятся в одной папке, то можно просто указать его название.

Несколько скриптов перечисляются в одной аннотации, а не несколькими подряд (`@file:Import` только один на скрипт):

```kotlin
@file:Import("../common/dialogue.kts", "../common/rewards.kts")
```

:::warning
Конструкция `@file:Import(...)` обязательно должна идти до классических импортов деклараций (`import ru.hollowhorizon.HollowEngine.*`)
:::

## Что импортируется?

Прежде всего стоит помнить, что импорт скриптов и импорт обычных Kotlin файлов это немного разные вещи. В скриптах можно писать логику и инструкции прямо на верхнем уровне, а не только внутри функций. Поэтому эти инструкции тоже будут выполнены.
<br/><br/>
В остальном всё работает также, все переменные, функции и классы внутри импортируемого скрипта станут доступны в основном скрипте.

```kotlin
// common/dialogue.kts
val narratorName = "Guide"

fun sayLine(player: Player, text: String) {
    player.say("$narratorName: $text")
}
```

```kotlin
// quest/intro.kts
@file:Import("../common/dialogue.kts")

// Теперь функция из скрипта `dialogue.kts` доступна в этом
sayLine(player, "The bridge is closed.")
```


## Общие скрипты

По умолчанию импортируемый скрипт выполняется отдельно для скрипта в котором он импортирован. То есть создав переменную и изменив её в одном скрипте, по умолчанию в другом скрипте она не изменится. Это можно изменить, добавив `@file:SharedScript`, если скрипт должен быть общим при импорте в любых других скриптах:

```kotlin
// common/dialogue.kts
@file:SharedScript

val dialogueHistory = mutableListOf<String>()

fun sayLine(text: String) {
    dialogueHistory += text
}
```

Тогда все скрипты, импортирующие `common/dialogue.kts`, будут обращаться к одному и тому же экземпляру и общей `dialogueHistory`. Это удобно для сервисов с общим состоянием во время работы игры, например, для системы диалогов, которая бы читалась в `.reload.kts`, а изменялась внутри `.node.kts`.

`SharedScript` импортирован по умолчанию, т.е. отдельный `import ...` для него не нужен. Аннотация должна находиться в начале файла, до обычных импортов.

:::warning
При изменении общего скрипта в работающем мире / игре может вызвать проблемы! Скрипты, которые уже успели запуститься, останутся со старыми классами, а перечитанные получат новые.

Например, если вы сохраняете и загружаете данные (например при старте/остановке сервера) об общем скрипте в `.reload.kts`, то изменив общий скрипт и прописав `/reload` старые обработчики будут отписаны до сохранения, а новые не вызовут загрузку данных для общего скрипта, по итогу данные из прошлой версии общего скрипта будут навсегда утеряны!

Для надёжности, при изменении общего скрипта лучше перезаходить в мир или игру.
:::
