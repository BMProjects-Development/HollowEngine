<center><h1>Импорты скриптов</h1></center>

Вынесите общие функции в отдельный файл и подключайте их в других скриптах. Так исправление одной функции сразу станет доступно всем, кто её использует.

![Навигация по импортам скриптов в IDE](/hollowengine/pictures/ide/code-navigation.webp)

Добавьте `@file:Import(...)` в начало файла. Ниже показана форма записи: `example.kts` должен существовать, а `functionFromExample()` - быть объявлен в нём.

```kotlin
@file:Import("example.kts")

functionFromExample()

```

Путь считается относительно текущего скрипта. Для такой структуры:

```text
hollowengine/
└─ scripts/
   ├─ quest/intro.node.kts
   └─ common/dialogue.kts
```

скрипт `quest/intro.node.kts` импортирует `common/dialogue.kts` так:

```kotlin
@file:Import("../common/dialogue.kts")

runSomeDialogue()

```

То есть две точки означают переход на папку выше относительно текущей. Если скрипты находятся в одной папке, то можно просто указать его название.

Несколько скриптов перечисляются в одной аннотации, а не несколькими подряд (`@file:Import` только один на скрипт):

```kotlin
@file:Import("../common/dialogue.kts", "../common/rewards.kts")
```

:::warning
Конструкция `@file:Import(...)` обязательно должна идти до классических импортов деклараций (`import net.minecraft.world.entity.player.Player`)
:::

## Что импортируется?

Импортированный скрипт тоже выполняет код верхнего уровня. Если он создаёт объект или печатает сообщение вне функции, это произойдёт при импорте. Его переменные, функции и классы затем доступны основному скрипту.

Создайте два файла из примера. `sayLine` получает игрока параметром, а вызывающая нода дожидается входа игрока `Steve`. Замените имя своим и запустите состояние `main`.

```kotlin
// common/dialogue.kts
import net.minecraft.network.chat.Component
import net.minecraft.world.entity.player.Player

val narratorName = "Guide"

fun sayLine(player: Player, text: String) {
    player.sendSystemMessage(Component.literal("$narratorName: $text"))
}
```

```kotlin
// quest/intro.node.kts
@file:Import("../common/dialogue.kts")

@State
suspend fun main() {
    playerRef("Steve").update {
        sayLine(this, "Мост закрыт.")
    }
}
```

## Одинаковые имена

Объявления всех импортированных скриптов попадают в одно пространство. Если два скрипта объявляют что-то с одним именем, то само объявление не мешает, но обращение к нему не скомпилируется (`Overload resolution ambiguity`): компилятор не знает, какое из двух имеется в виду.

```kotlin
// common/dialogue.kts
val title = "Диалоги"
```

```kotlin
// common/rewards.kts
val title = "Награды"
```

```kotlin
@file:Import("../common/dialogue.kts", "../common/rewards.kts")

println(title) // Ошибка: непонятно, какой из двух `title` вы написали
```

Проще всего дать объявлениям разные имена. Если это неудобно, задайте каждому скрипту свой пакет строкой `package`, как в обычном Kotlin-файле:

```kotlin
// common/dialogue.kts
package mypack.dialogue

val title = "Диалоги"
```

```kotlin
// common/rewards.kts
package mypack.rewards

val title = "Награды"
```

После этого объявления скрипта доступны только по полному имени или через обычный `import`, в том числе под другим именем:

```kotlin
@file:Import("../common/dialogue.kts", "../common/rewards.kts")

import mypack.dialogue.title as dialogueTitle
import mypack.rewards.*

println(dialogueTitle) // Диалоги
println(title) // Награды, пришёл из `import mypack.rewards.*`
```

:::warning
Порядок в начале файла такой: сначала аннотации `@file:...`, затем `package`, затем обычные `import`.
:::

Пакет скрипта - это только имя для Kotlin. Он не влияет ни на путь в `@file:Import`, ни на пространство имён предметов и блоков, которые регистрирует startup-скрипт.


## Общие скрипты

По умолчанию импортируемый скрипт выполняется отдельно для скрипта в котором он импортирован. То есть создав переменную и изменив её в одном скрипте, по умолчанию в другом скрипте она не изменится. Это можно изменить, добавив `@file:SharedScript`, если скрипт должен быть общим при импорте в любых других скриптах:

```kotlin
// common/dialogue.kts
@file:SharedScript

val dialogueHistory = mutableListOf<String>()

fun sayLine(text: String) {
    dialogueHistory += text
}
```

Тогда все скрипты, импортирующие `common/dialogue.kts`, будут обращаться к одному и тому же экземпляру и общей `dialogueHistory`. Это удобно для сервисов с общим состоянием во время работы игры, например, для системы диалогов, которая бы читалась в `.reload.kts`, а изменялась внутри `.node.kts`.

`SharedScript` импортирован по умолчанию, т.е. отдельный `import ...` для него не нужен. Аннотация должна находиться в начале файла, до обычных импортов.

[Startup-скрипты](/docs/hollowengine/scripting/startup#using-it-from-other-scripts) общие всегда, даже без аннотации: импорт отдаёт экземпляр, который выполнился при запуске игры, и он не сбрасывается при выходе из мира.

Общий скрипт компилируется в отдельный файл кэша и использует один экземпляр для всех импортирующих скриптов. При закрытии сервера мира этот экземпляр сбрасывается. Startup-скрипты сохраняют свой экземпляр до выхода из игры.

:::warning
Если изменить общий скрипт во время игры, работающие скрипты могут остаться со старыми классами, а перезагруженные получат новые.

Особенно внимательно проверяйте сохранение: `/reload` снимает старые обработчики, но не повторяет событие запуска сервера. Если загрузка и сохранение общего состояния зависят от этих событий, новые обработчики могут получить пустые данные и позже перезаписать прежние.

Сохраните мир перед изменением общего скрипта. После правки перезапустите мир или игру и проверьте восстановление данных.
:::
