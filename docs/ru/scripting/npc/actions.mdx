<center><h1>Действия и параллельность</h1></center>

*Как NPC может одновременно идти, смотреть по сторонам и работать руками, без единой строчки сложного кода с твоей стороны.*

Эта страница объясняет, как работают большинство действий связанных с нпс. Они используются во многих других системах (движение, инвентарь, поиск), поэтому перед ними лучше ознакомиться, как в целом работают действия.

## Что это и зачем?

Ранее уже были описаны функции вроде `wait(...)` или `npc.lookAt(...)`: это `suspend`-функции, то есть скрипт останавливается на этой строке и продолжает выполнение, когда действие завершится, не замораживая при этом всю игру (блоки продолжают ломаться, мобы ходить, другие скрипты продолжают работать).

```kotlin
@State
suspend fun main() {
    npc.lookAt(player)   // скрипт ждёт здесь, пока NPC не закончит поворот
    npc.move(player)     // затем ждёт здесь, пока NPC не дойдёт
}
```

Это отлично работает, но есть ограничение: скрипт делает только одно действие за раз. Если нужно, чтобы NPC **шёл к игроку, одновременно оглядываясь по сторонам и размахивая рукой**, обычная последовательность `suspend`-вызовов так не сможет, потому что каждая строка ждёт завершения предыдущей, прежде чем начать следующую.

Как вариант можно использовать `async` (см. [Асинхронные действия](/docs/hollowengine/scripting/node/async)), но отдельные `async`-блоки могут конфликтовать, например если два из них одновременно направляют NPC в разные точки.

Новая система действий решает именно эту задачу: она позволяет NPC делать несколько вещей **одновременно**, безопасно, без ручного управления потоками, блокировками или проверками "чем сейчас занят нпс, и как дать ему новую задачу, не ломая текущие?".

## Каналы

Каждое длительное действие NPC принадлежит определённому **каналу**. Канал - это просто именованный "слот", в котором в любой момент времени может находиться не больше одного выполняющегося действия. Есть четыре встроенных канала:

| Канал | За что отвечает | Где используется? |
|-------|--------------------|----------------------|
| `NpcActionKeys.MOVEMENT` | Передвижение | `move`, `startMove`, `collectItems` |
| `NpcActionKeys.LOOK` | Глаза/голова | `lookAt`, `startLookingAt` |
| `NpcActionKeys.HANDS` | Взаимодействие | `useBlock`, `destroyBlock`, `interact` |
| `NpcActionKeys.ANIMATION` | Состояние анимации | `startAnimation` |

Поскольку это четыре разных канала, NPC может одновременно идти (`MOVEMENT`), смотреть на игрока (`LOOK`) и размахивать инструментом (`HANDS`). Каждый канал просто делает своё дело независимо от остальных.

Чего канал делать *не может* - это держать сразу два действия. Если сказать нпс идти в точку A, а потом сразу же сказать им идти в точку B, разбираться с конфликтом вручную не нужно: **первый приказ просто заменяется вторым**. Старое движение останавливается, начинается новое.

:::advice
Запуск нового действия на занятом канале автоматически отменяет предыдущее действие. Это относится к движению, взгляду, рукам и пользовательским каналам.

`ANIMATION` является исключением: каждый вызов `startAnimation(...)` остаётся активным независимо. `npc.actions.cancel(NpcActionKeys.ANIMATION)` отменяет все работающие фоновые анимации.

:::

## Два способа вызвать действие

Каждая функция-действие (движение, взгляд, использование блока и так далее) существует в двух вариантах:

- **`suspend`-версия**: вызывается как `npc.move(target)`. Скрипт останавливается на этой строке и продолжает выполнение, когда действие завершится.
- **`startX`-версия**: вызывается как `npc.startMove(target)`. Скрипт **не ждёт**. Он сразу же получает обратно 'контроллер', который можно использовать позже, и сразу переходит к следующей строке.

```kotlin
@State
suspend fun main() {
    // Начинаем идти, но не ждём, сразу продолжаем.
    val walking = npc.startMove(player)

    // Пока NPC идёт, делаем что-то ещё одновременно с этим.
    npc.startAnimation("wave")

    // А теперь действительно ждём, пока движение завершится.
    val result = walking.await()
}
```

На самом деле `suspend` версия - это просто заранее написанный за тебя `startX(...).await()`. То есть `npc.move(target)` - это ровно то же самое, что `npc.startMove(target).await()`, так что переписывать всё на второй вариант, понятное дело, не нужно.

## Контроллер `NpcAction<R>`

Каждая функция `startX` возвращает объект для управления действием. У него есть четыре полезные вещи:

| Элемент | Значение |
|---------|----------|
| `.await()` | Остановиться здесь (внутри `suspend`-функции) и дождаться завершения действия, получив его результат. |
| `.cancel()` | Остановить действие прямо сейчас. |
| `.isActive` | `true`, пока действие ещё выполняется. |
| `.status` | Одно из значений `RUNNING`, `COMPLETED`, `CANCELLED`, `FAILED`. |

```kotlin
val walking = npc.startMove(player)

if (walking.isActive) {
    println("Всё ещё в пути")
}

walking.cancel() // Остановить раньше времени, например потому что игрок ушёл
```

## Остановка вручную

У двух встроенных каналов есть удобные короткие функции:

```kotlin
npc.stopMoving()       // отменяет то, что происходит на канале MOVEMENT
npc.clearLookTarget()  // отменяет то, что происходит на канале LOOK
```

Для любого канала, включая свои собственные (см. ниже), можно всегда отменить действие напрямую через `npc.actions`:

```kotlin
npc.actions.cancel(NpcActionKeys.HANDS)
npc.actions.cancel(NpcActionKeys.ANIMATION)
npc.actions.cancelAll() // остановить вообще всё, что делает NPC
```

`cancelAll()` удобно вызывать прямо перед `npc.despawn()` (хотя не то чтобы нужно), либо в любой момент, когда нужно сбросить NPC в полностью бездействующее состояние.

## Простой пример

```kotlin
@State
suspend fun main() {
    val playerRef = player.entityRef

    // Начинаем идти к игроку, не ждём.
    val walking = npc.startMove(playerRef)

    // Смотрим на игрока во время ходьбы, тоже не ждём.
    npc.startLookingAt(playerRef)

    // Анимация: машем рукой во время ходьбы.
    npc.startAnimation("wave")

    // Теперь ждём, пока само движение действительно не завершится.
    val result = walking.await()

    if (result == MoveResult.Arrived) {
        npc.say("Привет!")
    }
}
```

Все три канала работают независимо, поэтому NPC может выполнять несколько действий одновременно. Что означают значения `MoveResult`, смотри в разделе [Движение](/docs/hollowengine/scripting/npc/movement).

## Подвох, о котором стоит знать

Поскольку каналы общие для всего твоего скрипта (и для других скриптов и обработчиков нод, прикреплённых к той же сущности), обычный `suspend` вызов вроде `npc.move(...)` всё равно может быть прерван откуда-то ещё.

:::warning
Если обработчик `onInteract`, `onHurt` или любой другой из [ноды, прикреплённой к сущности](/docs/hollowengine/scripting/node), запускает новое действие на канале `MOVEMENT` для этого же NPC, пока `@State` находится в середине `npc.move(...)`, этот вызов будет отменён - точно так же, как если бы ты сам вызвал `stopMoving()`. Это ожидаемое поведение: последнее действие, запущенное на канале, всегда побеждает. Если две разные части логики постоянно перезапускают один и тот же канал, они будут постоянно прерывать друг друга.
:::

## Свои каналы (продвинутый уровень)

При необходимости можно завести свой ключ канала и работать напрямую через `npc.actions`, точно так же, как это делают встроенные функции внутри себя:

```kotlin
val CUSTOM_CHANNEL = NpcActionKey("my_mod:guard_patrol")

val patrol = npc.actions.start(CUSTOM_CHANNEL) {
    while (true) {
        npc.move(pointA)
        npc.move(pointB)
    }
}

// Повторный запуск автоматически отменяет предыдущий патруль.
npc.actions.start(CUSTOM_CHANNEL) { npc.move(pointC) }
```

Это ровно тот же механизм, который используют `move`, `lookAt` и другие встроенные функции, поэтому он ведёт себя согласованно с остальной системой.
