<center><h1>NPC вне мира</h1></center>

*Как NPC продолжает существовать, пока его чанк выгружен, и как его найти, изменить и не дать ему уйти туда, где его никто не прогрузит.*

Обычный моб Minecraft существует только внутри своего чанка: когда чанк выгружается, моб записывается в файл чанка, и пока игрок не вернётся, до него не дотянуться. NPC в HollowEngine устроены иначе. У каждого NPC есть **запись** в реестре NPC, которая хранится рядом с миром, как данные игроков, а `NpcEntity` в загруженном чанке - это лишь его **тело**.

Это даёт три вещи:

- NPC можно найти и изменить по UUID или по собственному id, даже когда рядом никого нет;
- перезапуск стадии истории не создаёт второго такого же персонажа;
- NPC всегда ровно один: чанки не сохраняют NPC, поэтому старое тело не появится где-то ещё после того, как NPC ушёл.

## Id: один NPC на имя

Если передать в `npc()` параметр `id`, вызов работает как "получить или создать":

```kotlin
@State
suspend fun main() {
    val smith = npc(
        pos = pos(10, 64, 10),
        name = "Кузнец",
        id = "village:blacksmith",
    )
}
```

Первый вызов создаёт NPC. Каждый следующий вызов с тем же id возвращает того же NPC, а остальные аргументы игнорирует, так что перезапущенная стадия или перезагруженный скрипт продолжают работать с уже существующим кузнецом, а не плодят толпу кузнецов. Без `id` каждый вызов, как и раньше, создаёт нового NPC.

Id в любой момент принадлежит только одному живому NPC. Используйте форму `namespace:name`, чтобы id из разных историй не пересекались.

## Поиск NPC

`npcs` даёт доступ ко всем NPC мира, загруженным и нет:

```kotlin
val smith = npcs["village:blacksmith"]   // по id
val byUuid = npcs[someUuid]              // по UUID
val around = npcs.near(overworld(), pos(0, 64, 0), 32.0) // в радиусе 32 блоков, сначала ближайшие
val everyone = npcs.all
```

Все они возвращают `NpcRef` (или `null`, если ничего не нашлось). В коде, где под рукой есть `MinecraftServer`, тот же объект доступен как `server.npcs`.

## `NpcRef`

`NpcRef` - это ссылка, которая остаётся действительной, что бы ни случилось с чанком. Её можно получить из реестра или у тела через `npc.ref`.

| Элемент | Значение |
|---------|----------|
| `resolve()` | Сущность NPC или `null`, если NPC удалён. См. ниже. |
| `isLoaded` | `true`, пока тело NPC стоит в загруженном чанке. |
| `exists` | `true`, пока NPC не удалён. |
| `isDead` | `true` для NPC, [сохранённого после смерти](#death-and-despawning). |
| `teleportTo(level, pos, yaw, pitch)` | Перемещает NPC; работает и без тела. |
| `despawn()` | Удаляет NPC насовсем, вместе с записью. |

```kotlin
val smith = npcs["village:blacksmith"] ?: return
smith.teleportTo(overworld(), pos(120, 70, -30))
```

Чтобы помнить NPC между перезапусками сервера, сохраняйте его UUID (или полагайтесь на id) и снова находите его через `npcs`. `entityRef<NpcEntity>(uuid)` тоже работает, но ждёт, пока тело появится в загруженном чанке.

## NPC без тела

`resolve()` всегда отдаёт `NpcEntity`. Если чанк загружен, это тело. Если нет, реестр собирает сущность из записи вне мира, и именно эта сущность станет телом, когда чанк загрузится.

Её можно читать и менять, как любого NPC: инвентарь, [данные](/docs/hollowengine/scripting/npc/data), компоненты. Изменения сохраняются вместе с миром.

```kotlin
val smith = npcs["village:blacksmith"]?.resolve() ?: return
smith.inventory.insert(ItemStack(Items.IRON_INGOT, 4))
```

:::warning
NPC без тела никто не тикает. Он не ходит, не оглядывается и не играет анимации, так что `move(...)` на нём никуда не приведёт. Сначала проверьте `isLoaded` или держите его чанки загруженными (см. ниже), если NPC должен действовать вдали от игроков.
:::

## Смерть и удаление

По умолчанию умерший NPC исчезает насовсем, как ванильный моб: его запись удаляется вместе с телом. `despawn()` и любой другой код, который удаляет тело (`discard()`), тоже удаляют запись.

Если истории мёртвый персонаж ещё нужен, например чтобы потом проверить, что игрок его убил, сохраните его запись:

```kotlin
boss.keepAfterDeath = true
```

После смерти такой NPC остаётся в реестре с `isDead == true`. Его тело больше не собирается, а `npc(...)` с его id создаёт на его месте нового NPC. Когда запись больше не нужна, вызовите `despawn()`.

## Загрузка чанков вокруг NPC

NPC ходит, только пока его чанк загружен. Если путь должен завершиться даже там, где нет игроков, держите чанки вокруг NPC загруженными на время действия:

```kotlin
courier.forceLoad {
    move(pos(800, 64, -1200))
}
```

Для NPC, который должен жить всегда и везде, включите флаг. Он сохраняется вместе с NPC, и после перезапуска сервера NPC вернётся сам:

```kotlin
courier.isForceLoaded = true
```

Загруженная область следует за NPC, куда бы он ни шёл.

:::caution
Каждый NPC, держащий чанки загруженными, нагружает сервер примерно как стоящий там игрок. Выключайте `isForceLoaded`, когда это больше не нужно, а для разовых походов предпочитайте `forceLoad { }`.
:::

## Где хранятся NPC

Записи лежат в `<мир>/hollowengine/npcs/`: по файлу `<uuid>.dat` на NPC и `index.dat`, благодаря которому сервер запускается, не читая всех NPC. В файлах чанков NPC больше нет.

NPC из миров, созданных до этого изменения, и NPC, созданные через `/summon`, попадают в реестр при первом появлении в загруженном чанке и дальше живут по этим правилам.

Клиент о реестре ничего не знает: игроки видят тела так же, как раньше.
