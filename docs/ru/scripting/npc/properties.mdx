<center><h1>Свойства NPC и сущностей</h1></center>

Меняйте имя, здоровье и поведение NPC через свойства Minecraft и компоненты HollowEngine. Ниже разберём, какие настройки доступны и как сохранять ссылку на персонажа.

---

## Главное отличие от старой документации

Переменная `npc` хранит объект `NpcEntity`. Он наследует возможности моба `PathfinderMob`, живой сущности `LivingEntity` и базовой сущности `Entity`. Например, здоровье доступно через свойство `health`, а положение - через `position()`.

В старых примерах встречаются динамические поля `Text`, `Bool` и `Position`. В Kotlin используйте свойства и функции из таблиц ниже.

Это значит:

- доступны стандартные Kotlin-свойства из Java getters/setters Minecraft;
- доступны методы Minecraft entity API;
- HollowEngine добавляет несколько удобных свойств и функций поверх них.

```kotlin
val npc = npc(pos(0, 64, 0), name = "Guide")

npc.setNameplate("New Guide")
npc.health = 20f

val id = npc.uuid
val position = npc.position()
val alive = npc.isAlive
```

## HollowEngine свойства `NpcEntity`

| Свойство | Тип | Чтение | Запись |
|----------|-----|--------|--------|
| `npc.pickupDistance` | зависит от `pickupReach` | Радиус подбора предметов. | Только чтение. |
| `npc.fakePlayer` | `ServerPlayer` | Служебный игрок, от имени которого NPC, например, ломает блоки. | Только чтение. |
| `npc.goals` | `GoalSelector` | Набор задач ИИ NPC. | Меняйте задачи через `npc.goals`. |
| `npc.inventory` | `NpcInventory` | Собственный инвентарь NPC, см. [Инвентарь и сбор предметов](/docs/hollowengine/scripting/npc/inventory). | Только чтение ссылки, менять через её функции. |
| `npc.data` | `EntityData` | Сохраняемые пользовательские данные, привязанные к NPC, см. [Пользовательские данные](/docs/hollowengine/scripting/npc/data). Доступно на любой `Entity`, не только на `NpcEntity`. | Только чтение ссылки, менять через её функции. |
| `npc.actions` | `NpcActionController` | Прямой доступ к каналам действий NPC, см. [Действия и параллельность](/docs/hollowengine/scripting/npc/actions). | Только чтение ссылки, менять через её функции. |

```kotlin
import ru.hollowhorizon.hollowengine.common.attachments.components.NameplateMode
import ru.hollowhorizon.hollowengine.common.entities.setNameplate

npc.setNameplate("Merchant", NameplateMode.SHOW)
```

## Часто используемые свойства Minecraft API

| Свойство / метод | Тип | Назначение |
|------------------|-----|------------|
| `npc.uuid` | `UUID` | Уникальный id сущности. |
| `npc.id` | `Int` | Runtime id сущности в мире. |
| `npc.position()` | `Vec3` | Текущая позиция. |
| `npc.x`, `npc.y`, `npc.z` | `Double` | Координаты сущности. |
| `npc.health` | `Float` | Текущее здоровье. |
| `npc.maxHealth` | `Float` | Максимальное здоровье. |
| `npc.isAlive` | `Boolean` | Жива ли сущность. |
| `npc.isCustomNameVisible` | `Boolean` | Видно ли имя над головой. |
| `npc.customName` | `Component?` | Minecraft-компонент имени. |
| `npc.mainHandItem` | `ItemStack` | Предмет в основной руке. |
| `npc.offhandItem` | `ItemStack` | Предмет во второй руке. |
| `npc.target` | `LivingEntity?` | Цель моба. |
| `npc.navigation` | `PathNavigation` | Pathfinding-навигация. |

Пример:

```kotlin
import net.minecraft.world.InteractionHand

npc.health = 10f
npc.isCustomNameVisible = true
npc.setItemInHand(InteractionHand.MAIN_HAND, item("minecraft:stick"))

val currentPos = npc.position()
val target = npc.target
```

## Компоненты вместо старых псевдо-свойств

Компонент объединяет связанные настройки сущности. Например, `Model` выбирает модель, а `BodyComponent` задаёт столкновения её основного тела:

```kotlin
import ru.hollowhorizon.hollowengine.common.attachments.api.set
import ru.hollowhorizon.hollowengine.common.attachments.components.BodyComponent
import ru.hollowhorizon.hollowengine.common.attachments.components.BodyMode
import ru.hollowhorizon.hollowengine.common.attachments.components.Model

npc.set(Model("hollowengine:models/entity/player_model.gltf"))
npc.set(BodyComponent(mode = BodyMode.BLOCKING))
```

Аниматор задайте в метаданных `.hemeta` выбранной модели через `animation-controller`. Встроенная модель игрока уже ссылается на `hollowengine:standard_player`.

Для анимаций смотрите раздел [Анимации](/docs/hollowengine/models/animations).

## Сохранение ссылок на NPC

Не сохраняйте сам объект `NpcEntity` между перезагрузками. Сохраняйте UUID:

```kotlin
val tag = stateTag()
tag.putUUID("guide", npc.uuid)
```

После загрузки используйте `entityRef<NpcEntity>(uuid)` (параметр типа обязателен):

```kotlin
val guideRef = entityRef<NpcEntity>(tag.getUUID("guide"))
val guide = guideRef.resolve()
```

Это безопаснее, чем держать прямую ссылку на сущность, потому что Minecraft может выгрузить или пересоздать entity. `entityRef` ждёт, пока тело загрузится; чтобы добраться до NPC в выгруженном чанке, используйте `npcs[uuid]` или его id, см. [NPC вне мира](/docs/hollowengine/scripting/npc/registry).

## Неймплейты

Используйте API HollowEngine для неймплейта вместо ручного сочетания `customName` и `isCustomNameVisible`. Он работает с `NpcEntity` и другими сущностями, синхронизируется с клиентами и сохраняется вместе с сущностью.

```kotlin
import ru.hollowhorizon.hollowengine.common.entities.nameplateMode
import ru.hollowhorizon.hollowengine.common.entities.setNameplate
import ru.hollowhorizon.hollowengine.common.attachments.components.NameplateMode

npc.setNameplate("Торговец", NameplateMode.SHOW_ON_HOVER)
npc.nameplateMode = NameplateMode.SHOW
npc.nameplateMode = NameplateMode.HIDDEN
```

`SHOW` использует обычную отрисовку имени Minecraft. `HIDDEN` скрывает неймплейт. `SHOW_ON_HOVER` показывает его только когда игрок смотрит на сущность.

`Entity.name` остаётся отображаемым `Component` Minecraft и доступен только для чтения. `customName` это низкоуровневый vanilla `Component?`, которым заменяется имя. Он нужен, когда требуется форматированный или переводимый компонент. Основной API для скриптов это `setNameplate(text, mode)`: он сразу назначает простой текст и режим видимости. `nameplateMode` меняет только режим, сохраняя текущий `customName`.
