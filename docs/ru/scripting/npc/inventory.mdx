<center><h1>Инвентарь и сбор предметов</h1></center>

*Теперь у каждого NPC есть собственный инвентарь, способ описать "какие предметы" и фоновая задача, которая сама ходит и их собирает.*

![Редактор инвентаря NPC](/hollowengine/pictures/npc/inventory.webp)

## Инвентарь NPC

Каждый `npc()` получает собственный инвентарь, `npc.inventory`, с 36 слотами по умолчанию (можно поменять через параметр `inventorySize` у `npc(...)`, см. [Создание NPC](/docs/hollowengine/scripting/npc/create)). Он автоматически сохраняется и восстанавливается вместе со всеми зачарованиями, кастомными именами и другими компонентами данных каждого предмета.

Корооткие функции для упрощённой работы с инвентарём:

```kotlin
npc.giveItem(item("minecraft:bread", 5))          // положить предметы
npc.takeItems(itemFilter(item("minecraft:bread")), 2) // забрать 2 хлеба обратно
npc.countItems(itemFilter(item("minecraft:bread")))   // сколько хлеба у него есть?
npc.hasItems(itemFilter(item("minecraft:bread")).request(3)) // есть ли хотя бы 3?
```

| Функция | Что делает |
|---------|-------------|
| `giveItem(stack)` | Добавляет стак, возвращает то, что не поместилось (пусто, если поместилось всё). |
| `giveItems(stacks)` | То же самое сразу для нескольких стаков, возвращает список того, что не поместилось. |
| `takeItems(filter, count)` | Удаляет до `count` подходящих предметов и возвращает их. |
| `countItems(filter)` | Считает, сколько подходящих предметов несёт NPC. |
| `hasItems(request)` / `hasItems(requests)` | Проверяет, хватает ли у NPC одного или нескольких запрошенных наборов. |
| `dropItems(filter, count)` | Удаляет подходящие предметы и выбрасывает их на землю. |
| `transferItems(target, filter, count)` | Переносит предметы напрямую из инвентаря этого NPC в инвентарь другого NPC или игрока. |
| `equip(slot, filter)` | Находит подходящий предмет в инвентаре и надевает его в указанный `EquipmentSlot` (старый предмет, если был, возвращается в инвентарь). |
| `unequip(slot)` | Снимает текущий надетый предмет из слота обратно в инвентарь. |

```kotlin
import net.minecraft.world.entity.EquipmentSlot

npc.equip(EquipmentSlot.MAINHAND, itemTag("minecraft:swords"))
npc.unequip(EquipmentSlot.MAINHAND)
```

:::advice
`giveItem` и `giveItems` автоматически складывают предметы в стаки, до обычного максимального размера стака, и переходят к пустым слотам только когда подходящие стаки уже заполнены. Если дать 70 яблок в инвентарь, где есть место только на 64, вернётся стак из 6 яблок - та часть, что не поместилась, так что можно самому решить, что с ней делать (выбросить, отменить сделку и так далее):

```kotlin
val leftover = npc.giveItem(item("minecraft:apple", 70))
if (!leftover.isEmpty) npc.dropItem(leftover)
```
:::

:::warning
`equip` возвращает ранее надетый предмет (если был) обратно в инвентарь. Если в этот момент инвентарь полностью заполнен, положить его некуда, и `equip` выбросит ошибку. У `unequip` такой проблемы нет - он возвращает `false`, если предмет не поместился, и то, что не поместилось, остаётся надетым. Перед вызовом `equip` на инвентаре, который может быть заполнен, лучше проверьте `countItems` заранее или оставьте хотя бы один свободный слот.
:::

## Прямой доступ к слотам

Функции выше покрывают частые случаи, но иногда нужно работать с инвентарём как с обычным списком слотов.

```kotlin
val allItems: List<ItemStack> = npc.inventory.contents()      // копия каждого слота, включая пустые
val firstSlot: ItemStack = npc.inventory.get(0)                // прочитать конкретный слот
npc.inventory.set(0, item("minecraft:torch", 16))              // перезаписать конкретный слот, вернёт то, что там было раньше

val overflow = npc.inventory.resize(9)                          // изменить количество слотов
overflow.forEach(npc::dropItem)                                 // предметы, которым не хватило места, возвращаются сюда

val removed = npc.inventory.clear()                             // очистить весь инвентарь, вернёт то, что было удалено
```

| Функция | Что делает |
|---------|-------------|
| `contents()` | Все слоты как `List<ItemStack>`, включая пустые стаки, по порядку. |
| `get(slot)` | Читает один слот по индексу. |
| `set(slot, stack)` | Перезаписывает один слот, возвращает то, что там было раньше. |
| `resize(size)` | Меняет количество слотов. Если инвентарь уменьшается и некоторым предметам не хватило слота, они возвращаются вместо того, чтобы удалиться, так что их можно выбросить, залогировать или отменить изменение размера. |
| `clear()` | Очищает все слоты сразу, возвращает всё, что было удалено. |

## Как описать "какие предметы": фильтры и запросы

Прежде чем давать, забирать, считать или искать предметы, нужен способ сказать, *какие именно* предметы имеются в виду. Для этого существуют `ItemFilter` и `ItemRequest`.

- **`ItemFilter`** отвечает на вопрос да/нет про один `ItemStack`: "это подходит?". У него нет привязанного количества.
- **`ItemRequest`** - это фильтр плюс нужное количество: "10 штук вот этого".

### Создание фильтра

```kotlin
val bread = itemFilter(item("minecraft:bread"))                 // именно хлеб, совпадает предмет и любое имя/компоненты
val logs = itemTag("minecraft:logs")                            // всё, что входит в тег предметов minecraft:logs
val anyStick = itemFilter(item("minecraft:stick"), match = ItemMatchMode.ITEM_ONLY) // любая палка, игнорируя имя/компоненты
```

По умолчанию `itemFilter(...)` сравнивает и тип предмета, и его компоненты данных (зачарования, кастомное имя и так далее), поэтому обычная палка не совпадёт с палкой с именем "Magic Stick", если не передать `match = ItemMatchMode.ITEM_ONLY`.

Можно также написать свой фильтр из любого условия:

```kotlin
val enchantedOnly = itemFilter { stack -> stack.isEnchanted }
```

Комбинирование фильтров:

```kotlin
val fruit = anyOf(itemTag("minecraft:apple"), itemTag("minecraft:pumpkins")) // яблоко или тыква
val cheapTool = allOf(itemTag("minecraft:pickaxes"), not(itemFilter { it.isEnchanted })) // кирка без зачарований
```

### Создание запроса (фильтр с количеством)

```kotlin
val need = logs.request(10)                       // 10 штук того, что подходит под "logs" (фильтр)
val need2 = itemRequest(item("minecraft:bread", 5)) // 5 хлеба, количество берётся из count стака
```

`itemRequests(vararg templates)` строит список запросов сразу из нескольких стаков, удобно, когда нужно "5 хлеба и 3 яблока" одним вызовом.

## Отправить NPC собирать предметы: `collectItems`

Это готовая фоновая задача: вы указываете NPC список запросов, и он **сам ходит вокруг, подбирает подходящие выпавшие предметы и возвращается назад**.

```kotlin
@State
suspend fun main() {
    val result = npc.collectItems(
        listOf(itemTag("minecraft:logs").request(10)),
        CollectOptions(radius = 20.0),
    )

    when (result.reason) {
        CollectStopReason.COMPLETED -> npc.say("Всё собрал!")
        CollectStopReason.INVENTORY_FULL -> npc.say("Мои сумки полны.")
        CollectStopReason.NO_CANDIDATES -> npc.say("Поблизости не вижу брёвен.")
        CollectStopReason.NO_REACHABLE_CANDIDATES -> npc.say("Вижу брёвна, но не могу до них добраться.")
    }
}
```

`collectItems` - обычная `suspend` функция, поэтому строка выше ждёт, пока NPC не закончит (или не сдастся). Как и любое другое длительное действие, у неё тоже есть `startCollectItems(...)` для фоновой формы, описанной в [Действиях и параллельности](/docs/hollowengine/scripting/npc/actions), и она работает на общем канале `MOVEMENT`, поэтому будет отменена так же, как обычный `move(...)`.

### Что происходит по шагам

Пока `collectItems` работает, NPC сам повторяет такой цикл:

1. Найти ближайший выпавший предмет, подходящий под ещё не выполненный запрос, в пределах `radius`.
2. Если ничего не найдено - либо подождать и проверить снова (`WAIT_AND_RETRY`), либо остановиться (`FAIL`), в зависимости от указанной `searchPolicy`.
3. Дойти до предмета и подобрать его.
4. Если в инвентаре не осталось места, остановиться с `CollectStopReason.INVENTORY_FULL`.
5. Повторять, пока все запросы не будут выполнены, а затем, по умолчанию, вернуться туда, где NPC начал, и восстановить исходное направление взгляда.

### `CollectOptions`

| Поле | По умолчанию | Значение |
|------|--------------|----------|
| `radius` | `16.0` | Насколько далеко вокруг NPC искать предметы. |
| `movement` | завершается ошибкой при недостижимости/недоступности | `MoveOptions`, используемые при ходьбе к каждому предмету, см. [Движение](/docs/hollowengine/scripting/npc/movement). |
| `searchPolicy` | `WAIT_AND_RETRY` | Что делать, если сейчас не видно подходящего предмета: продолжать ждать или сдаться. |
| `searchIntervalTicks` | `10` | Как часто проверять снова во время ожидания. |
| `returnToStart` | `true` | Возвращаться ли NPC на исходное место (и в исходную позу) после завершения. |

### `CollectResult`

| Поле | Значение |
|------|----------|
| `collected` | Реально подобранные предметы, в виде списка `CollectedItem(stack)`. |
| `remaining` | Запросы, которые не были выполнены полностью, если такие есть (пусто при полном успехе). |
| `reason` | Почему задача остановилась, см. `CollectStopReason` выше. |
| `returnResult` | `MoveResult` обратного пути домой, либо `null`, если `returnToStart = false`. |

:::advice
Если два разных NPC одновременно отправятся за одной и той же кучей выпавших предметов, они не будут драться за один и тот же стак: как только один NPC уже идёт подбирать какой-то предмет, поиск у второго NPC автоматически пропускает этот предмет и ищет другой.
:::

## Собираем всё вместе: простой продавец

`hasItems`, `takeItems` и `giveItem` работают с `npc.inventory`, поэтому продавцу, торгующему из собственных запасов, хватит функций с этой страницы. Магазину нужно реагировать на взаимодействия всё время, пока NPC существует, а для этого как раз нужен [node-скрипт, прикреплённый к сущности](/docs/hollowengine/scripting/node):

```kotlin
@file:Attach(ru.hollowhorizon.hollowengine.common.entities.NpcEntity::class)

// Сама сущность здесь - implicit receiver, поэтому префикс `npc.` не нужен.
giveItem(item("minecraft:bread", 32)) // завозим товар один раз, когда нода запускается

onInteract { event ->
    val bread = itemFilter(item("minecraft:bread"))
    if (hasItems(bread.request(1))) {
        transferItems(event.player, bread, 1)
        say("Держи хлеб!")
    } else {
        say("Всё распродано, пошёл вон.")
    }
}
```

`transferItems` принимает игрока в качестве цели, так что хлеб уходит из запасов NPC и попадает в инвентарь игрока за один шаг, а игрок без свободного слота просто ничего не получит, вместо того чтобы предмет исчез. У стороны игрока есть свои функции, см. [Инвентарь игрока](/docs/hollowengine/scripting/player). Если пишете это внутри сцены `@State`, где NPC - локальная переменная, используйте `npc.hasItems(...)`, `npc.takeItems(...)` и `npc.giveItem(...)`, как и везде на этой странице.

## Пример: надеть лучшее оружие из имеющегося

```kotlin
@State
suspend fun main() {
    npc.giveItems(
        listOf(
            item("minecraft:wooden_sword"),
            item("minecraft:iron_sword"),
        ),
    )

    // Предпочитаем железный меч, а если его нет - берём любой меч по тегу.
    val equipped = npc.equip(EquipmentSlot.MAINHAND, itemFilter(item("minecraft:iron_sword"), match = ItemMatchMode.ITEM_ONLY))
        || npc.equip(EquipmentSlot.MAINHAND, itemTag("minecraft:swords"))

    if (!equipped) {
        npc.say("Мне нечем сражаться((")
    }
}
```
