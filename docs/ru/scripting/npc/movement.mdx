<center><h1>Движение и взаимодействие</h1></center>

*Ходьба, взгляд, использование блоков и взаимодействие с сущностями.*

Рекомендуется сначала прочитать [Действия и параллельность](/docs/hollowengine/scripting/npc/actions): каждая функция здесь существует в `suspend`-форме (ждёт действие) и в форме `startX` (работает в фоне и отдаёт контроллер), и каждая использует один из каналов `MOVEMENT`, `LOOK` или `HANDS`.

## Движение к сущности или позиции

```kotlin
npc move player                               // к сущности, дистанция и скорость по умолчанию
npc.move(player, dist = 2.0, speed = 1.2)     // к сущности, свои дистанция и скорость
npc move pos(10, 64, 10)                      // к позиции, по умолчанию
npc.move(pos(10, 64, 10), dist = 0.5)         // к позиции, своя дистанция
```

Все это `suspend` функции: скрипт ждёт, пока NPC дойдёт (или не сдастся). У каждой из них есть двойник `startMove(...)`, который сразу возвращает `NpcAction<MoveResult>` - контроллер, описанный в [Действиях и параллельности](/docs/hollowengine/scripting/npc/actions).

```kotlin
val walking = npc.startMove(player) // не ждёт
// ... делаем что-то ещё ...
val result = walking.await()
```

### Что возвращает `move`

Функции движения возвращают `MoveResult`, поэтому можно узнать, что реально произошло, а не просто считать, что NPC дошёл:

| Значение | Значит |
|----------|--------|
| `MoveResult.Arrived` | NPC достиг нужной дистанции до цели. |
| `MoveResult.Unreachable` | Путь не удалось найти в течение какого-то времени (см. `unreachable` ниже). |
| `MoveResult.TargetUnavailable` | Целевая сущность исчезла, сменила измерение или её ссылка устарела (см. `unavailableTarget` ниже). |
| `MoveResult.Closest(reason, distance)` | NPC остановился так близко к точке, как смог, в `distance` блоках от неё. `reason` - почему (см. [Как можно ближе](#getting-as-close-as-it-can)). |

```kotlin
val result = npc.move(player)
if (result != MoveResult.Arrived) {
    npc.say("Я заблудился((")
}
```

:::advice
Если важно только "иди туда, проверять ничего не нужно", можно продолжать игнорировать возвращаемое значение, точно как в старых скриптах. Проверка `MoveResult` не обязательна, она нужна тогда, когда требуется отреагировать на неудачную попытку дойти.
:::

### Тонкая настройка движения через `MoveOptions`

Для полного контроля передайте `MoveOptions` вместо `dist`/`speed`:

```kotlin
npc.move(
    player,
    MoveOptions(
        speed = 1.2,
        arrivalDistance = 2.0,
        unreachable = UnreachablePolicy.FAIL,
    ),
)
```

| Поле | По умолчанию | Значение |
|------|--------------|----------|
| `speed` | `1.0` | Скорость передвижения. |
| `arrivalDistance` | `1.5` | Насколько близко нужно подойти в блоках, чтобы считалось "нпс дошёл". NPC тормозит так, чтобы остановиться на этом расстоянии. `0` - подойти вплотную к точке, насколько получится. |
| `facing` | `Facing.Path` | Куда NPC смотрит на ходу движения; см. [Куда смотрит NPC](#which-way-the-npc-faces). |
| `passDistance` | `1.0` | Насколько близко нужно подойти к точке, через которую путь только проходит, чтобы она считалась пройденной; см. [Путь через несколько точек](#walking-through-several-points). |
| `avoid` | нет | Зоны, которые это перемещение обходит; см. [Обход зон](#keeping-out-of-zones). |
| `navigation` | нет | Меняет [настройки навигации](/docs/hollowengine/scripting/npc/navigation) NPC только на это перемещение. |
| `repathIntervalTicks` | `10` | Как часто нпс пересчитывает путь во время движения. |
| `targetMoveThreshold` | `1.0` | Если движущаяся цель (например, игрок) сдвинулась дальше этого значения с момента последнего построения пути, NPC пересчитывает путь немедленно, не дожидаясь следующего интервала. |
| `stuckTimeoutTicks` | `60` | Если нпс не продвигается столько тиков подряд, он считается застрявшим, и путь пересчитывается принудительно. |
| `unreachableTimeoutTicks` | `40` | Сколько времени поиску пути разрешено продолжать проваливаться, прежде чем сработает `unreachable`. |
| `unreachable` | `WAIT_AND_RETRY` | Что делать, если путь не находится (см. ниже). |
| `unavailableTarget` | `WAIT_AND_RETRY` | Что делать, если целевая сущность пропала или стала невалидной (см. ниже). |

Обе политики работают одинаково: `WAIT_AND_RETRY` пытается бесконечно (удобно для "просто дойди туда рано или поздно" в постановочных сценах), а `FAIL` сдаётся и возвращает `MoveResult.Unreachable` / `MoveResult.TargetUnavailable` или `MoveResult.Closest` с `NO_PATH` или `BLOCKED`, чтобы скрипт мог сам решить, что делать дальше.

```kotlin
enum class UnreachablePolicy { WAIT_AND_RETRY, FAIL }
enum class UnavailableTargetPolicy { WAIT_AND_RETRY, FAIL }
```

Как NPC ищет путь и идёт по нему. Прыжки, скорость на прямых и в поворотах, блоки, которые он обходит - всё настраивается у каждого NPC [компонентом «Навигация»](/docs/hollowengine/scripting/npc/navigation).

### Как можно ближе

Если тело NPC не может встать в точку: она в стене, в воздухе или слишком близко к забору для его ширины, NPC не ждёт там вечно. Он идёт к ближайшему месту в пределах двух блоков от точки, где может встать, и там перемещение заканчивается с `MoveResult.Closest`. `reason` - одно из:

| `Shortfall` | Значит | Когда |
|-------------|--------|-------|
| `NO_ROOM` | В точке нет места для NPC; он встал на ближайшее место, где оно есть. | Всегда, что бы ни стояло в `unreachable`. |
| `NO_PATH` | К точке не ведёт ни один путь; NPC прошёл так далеко, как путь позволяет. | При `unreachable = FAIL`; при `WAIT_AND_RETRY` он ждёт там и пробует снова. |
| `BLOCKED` | На пути то, что NPC не может ни обойти, ни растолкать: дважды подряд за `stuckTimeoutTicks` он никуда не продвинулся. | При `unreachable = FAIL`; при `WAIT_AND_RETRY` он пробует снова. |

```kotlin
when (val result = npc.move(pos(10, 64, 10), MoveOptions(arrivalDistance = 0.0, unreachable = UnreachablePolicy.FAIL))) {
    MoveResult.Arrived -> npc.say("Я на месте.")
    is MoveResult.Closest -> when (result.reason) {
        Shortfall.NO_ROOM -> npc.say("Ближе мне не встать.")
        Shortfall.NO_PATH -> npc.say("Туда не пройти.")
        Shortfall.BLOCKED -> npc.say("Мне кто-то мешает.")
    }
    else -> {}
}
```

Промежуточная точка [пути через несколько точек](#walking-through-several-points), в которой нет места, считается пройденной в ближайшем к ней месте.

### Путь через несколько точек

Если передать в `move` список точек, NPC пройдёт их по очереди и остановится только в последней:

```kotlin
val route = [pos(10, 64, 10), pos(20, 64, 10), pos(20, 64, 25)]
npc.move(route)
npc.move(route, MoveOptions(passDistance = 2.0, arrivalDistance = 0.5))
```

Точка до последней считается пройденной, когда NPC подошёл к ней на `passDistance`, а `arrivalDistance` относится к последней. Темп NPC рассчитывает по ещё не пройденным точкам, поэтому проходит точку как обычный поворот, дугой, и тормозит только перед последней. Если в точке нужно постоять или осмотреться, это отдельные перемещения. `startMove(points)` - фоновая форма.

### Куда смотрит NPC

По умолчанию NPC смотрит туда, куда идёт. `facing` держит его взгляд на чём-то другом, а идёт он тогда боком или задом - медленнее, по [скоростям назад и вбок](/docs/hollowengine/scripting/npc/navigation#movement) из его настроек:

```kotlin
npc.move(pos(0, 64, 5), MoveOptions(facing = Facing.at(player)))   // пятится от игрока, не спуская с него глаз
npc.move(pos(0, 64, 5), MoveOptions(facing = Facing.at(pos(0, 64, 0))))
npc.move(pos(0, 64, 5), MoveOptions(facing = Facing.Yaw(90f)))
```

| Значение | Смотрит |
|----------|---------|
| `Facing.Path` | туда, куда идёт |
| `Facing.at(entity)` | на сущность, пока она есть |
| `Facing.at(position)` | на позицию |
| `Facing.Yaw(degrees)` | в заданную сторону, угол как у ванильного yaw |

Короткий путь до точки за спиной NPC и без `facing` проходит задом сам: см. **Шаг назад** в его [настройках](/docs/hollowengine/scripting/npc/navigation#movement). Для прыжка через яму NPC разворачивается к месту приземления, а приземлившись, поворачивается обратно. В конце перемещения NPC доворачивается к тому, на что смотрел, и только потом перемещение завершается.

[`lookAt`](#looking-at-something) на ходу работает как `facing`: корпус поворачивается к тому, на что NPC смотрит, а сам он идёт боком или задом. Побеждает то, что было вызвано позднее. Когда `lookAt` заканчивается, возвращается `facing` перемещения.

### Обход зон

`Zone` - коробка или сфера в мире. NPC либо никогда в неё не заходит, либо обходит её с настраиваемой ценой за каждый её блок на пути; блок считается в зоне, если в ней его середина.

```kotlin
val yard = Zone.box(pos(0, 60, 0), pos(10, 70, 10))           // не заходит никогда
val flowers = Zone.sphere(pos(5, 64, 20), 3.0, cost = 6f)     // обходит, если это того стоит

npc.move(pos(30, 64, 30), MoveOptions(avoid = listOf(yard, flowers)))   // на одно перемещение
npc.avoid(yard)                                                          // на любое движение
npc.stopAvoiding(yard)
npc.stopAvoidingAll()
```

Зона из `avoid(...)` действует на любое движение NPC, включая его цели, пока скрипт её не снимет. С NPC она не сохраняется: если она нужна после перезагрузки, скрипт добавляет её снова. NPC, стоящий внутри зоны, в которую ему нельзя, выходит из неё кратчайшим путём и больше туда не заходит.

### Остановка

```kotlin
npc.stopMoving()
```

Отменяет то, куда NPC сейчас идёт, и немедленно останавливает его навигацию.

## Взгляд на объект

```kotlin
npc.lookAt(pos(0, 64, 0))
npc.lookAt(player)
```

Плавно поворачивает голову и тело NPC к позиции или сущности примерно за 1.5 секунды (это `suspend` форма, которая ждёт). Если NPC при этом идёт, он поворачивает к цели корпус и идёт дальше боком или задом, см. [Куда смотрит NPC](#which-way-the-npc-faces). Используйте `startLookingAt(...)` для фоновой формы и `clearLookTarget()`, чтобы отменить её раньше времени:

```kotlin
npc.startLookingAt(player)  // не ждёт
npc.clearLookTarget()       // отменить
```

### Мгновенный, потиковый поворот: `lookAtNow`

`lookAtNow` отличается от остальной части этой страницы. Он сразу поворачивает NPC на указанный угол, один раз, и возвращает, достаточно ли близко NPC уже повёрнут к цели, чтобы считать, что он "смотрит" на неё:

```kotlin
val facing: Boolean = npc.lookAtNow(player, maxAngularSpeed = 360f)
```

Есть два способа использовать `lookAtNow`: вызывать функцию каждый тик, например из обработчика `onUpdate { ... }` в [node-скрипте](/docs/hollowengine/scripting/node), с небольшим `maxAngularSpeed` для плавного поворота и слежения за движущейся целью или вызвать её один раз с большим `maxAngularSpeed`, чтобы мгновенно установить угол поворота NPC.

## Использование блока

```kotlin
npc.useBlock(pos(10, 64, 10))
```

Ведёт NPC к блоку, разворачивает его лицом к блоку и использует блок основной рукой - полезно для рычагов, кнопок и других интерактивных блоков (блоки могут использовать только игроки, так что не факт, что оно сработает на чём-то из модов). Дополнительные параметры:

```kotlin
npc.useBlock(pos(10, 64, 10), hand = InteractionHand.OFF_HAND, reach = 4.0)
```

`useBlockNow(pos, ...)` делает то же самое мгновенно, без ходьбы и ожидания, и срабатывает только если NPC уже находится в пределах `reach`. `startUseBlock(...)` - фоновая форма.

:::warning
`useBlock`, `destroyBlock` и `interact` сначала ведут NPC к цели, и для этого используют тот же канал `MOVEMENT`, что и `move`/`startMove`. Если NPC уже куда-то шёл в фоне, это движение будет заменено - действует то же правило из [Действий и параллельности](/docs/hollowengine/scripting/npc/actions).
:::

## Разрушение блока

```kotlin
npc.destroyBlock(pos(10, 64, 10))
```

Ведёт NPC к блоку, разворачивает лицом к нему и ломает блок, как это сделал бы fake player (по умолчанию учитывая требования к инструменту). Установите `requireCorrectTool = false`, чтобы NPC мог ломать блоки без подходящего инструмента. `startDestroyBlock(...)` - фоновая форма.

## Взаимодействие с сущностью

```kotlin
npc.interact(playerRef)
```

Ведёт NPC к целевой сущности и взаимодействует с ней указанной рукой (по сути, аналог правого клика по ней). `interactNow(target, ...)` делает то же самое мгновенно, если цель уже в радиусе досягаемости, без ходьбы. `startInteract(...)` - фоновая форма.

```kotlin
val result: InteractionResult = npc.interactNow(someEntity)
```
