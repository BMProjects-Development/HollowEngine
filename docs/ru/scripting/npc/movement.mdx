<center><h1>Движение и взаимодействие</h1></center>

*Ходьба, взгляд, использование блоков и взаимодействие с сущностями.*

Рекомендуется сначала прочитать [Действия и параллельность](/docs/hollowengine/scripting/npc/actions): каждая функция здесь существует в `suspend`-форме (ждёт действие) и в форме `startX` (работает в фоне и отдаёт контроллер), и каждая использует один из каналов `MOVEMENT`, `LOOK` или `HANDS`.

## Движение к сущности или позиции

```kotlin
npc move player                               // к сущности, дистанция и скорость по умолчанию
npc.move(player, dist = 2.0, speed = 1.2)     // к сущности, свои дистанция и скорость
npc move pos(10, 64, 10)                      // к позиции, по умолчанию
npc.move(pos(10, 64, 10), dist = 0.5)         // к позиции, своя дистанция
```

Все это `suspend` функции: скрипт ждёт, пока NPC дойдёт (или не сдастся). У каждой из них есть двойник `startMove(...)`, который сразу возвращает `NpcAction<MoveResult>` - контроллер, описанный в [Действиях и параллельности](/docs/hollowengine/scripting/npc/actions).

```kotlin
val walking = npc.startMove(player) // не ждёт
// ... делаем что-то ещё ...
val result = walking.await()
```

### Что возвращает `move`

Функции движения возвращают `MoveResult`, поэтому можно узнать, что реально произошло, а не просто считать, что NPC дошёл:

| Значение | Значит |
|----------|--------|
| `MoveResult.Arrived` | NPC достиг нужной дистанции до цели. |
| `MoveResult.Unreachable` | Путь не удалось найти в течение какого-то времени (см. `unreachable` ниже). |
| `MoveResult.TargetUnavailable` | Целевая сущность исчезла, сменила измерение или её ссылка устарела (см. `unavailableTarget` ниже). |

```kotlin
val result = npc.move(player)
if (result != MoveResult.Arrived) {
    npc.say("Я заблудился((")
}
```

:::advice
Если важно только "иди туда, проверять ничего не нужно", можно продолжать игнорировать возвращаемое значение, точно как в старых скриптах. Проверка `MoveResult` не обязательна, она нужна тогда, когда требуется отреагировать на неудачную попытку дойти.
:::

### Тонкая настройка движения через `MoveOptions`

Для полного контроля передай `MoveOptions` вместо `dist`/`speed`:

```kotlin
npc.move(
    player,
    MoveOptions(
        speed = 1.2,
        arrivalDistance = 2.0,
        unreachable = UnreachablePolicy.FAIL,
    ),
)
```

| Поле | По умолчанию | Значение |
|------|--------------|----------|
| `speed` | `1.0` | Скорость передвижения. |
| `arrivalDistance` | `1.5` | Насколько близко нужно подойти в блоках, чтобы считалось "нпс дошёл". |
| `repathIntervalTicks` | `10` | Как часто нпс пересчитывает путь во время движения. |
| `targetMoveThreshold` | `1.0` | Если движущаяся цель (например, игрок) сдвинулась дальше этого значения с момента последнего построения пути, NPC пересчитывает путь немедленно, не дожидаясь следующего интервала. |
| `stuckTimeoutTicks` | `60` | Если нпс не продвигается столько тиков подряд, он считается застрявшим, и путь пересчитывается принудительно. |
| `unreachableTimeoutTicks` | `40` | Сколько времени поиску пути разрешено продолжать проваливаться, прежде чем сработает `unreachable`. |
| `unreachable` | `WAIT_AND_RETRY` | Что делать, если путь не находится (см. ниже). |
| `unavailableTarget` | `WAIT_AND_RETRY` | Что делать, если целевая сущность пропала или стала невалидной (см. ниже). |

Обе политики работают одинаково: `WAIT_AND_RETRY` пытается бесконечно (удобно для "просто дойди туда рано или поздно" в постановочных сценах), а `FAIL` сдаётся и возвращает `MoveResult.Unreachable` / `MoveResult.TargetUnavailable`, чтобы скрипт мог сам решить, что делать дальше.

```kotlin
enum class UnreachablePolicy { WAIT_AND_RETRY, FAIL }
enum class UnavailableTargetPolicy { WAIT_AND_RETRY, FAIL }
```

### Остановка

```kotlin
npc.stopMoving()
```

Отменяет то, куда NPC сейчас идёт, и немедленно останавливает его навигацию.

## Взгляд на объект

```kotlin
npc.lookAt(pos(0, 64, 0))
npc.lookAt(player)
```

Плавно поворачивает голову и тело NPC к позиции или сущности примерно за 1.5 секунды (это `suspend` форма, которая ждёт). Используй `startLookingAt(...)` для фоновой формы и `clearLookTarget()`, чтобы отменить её раньше времени:

```kotlin
npc.startLookingAt(player)  // не ждёт
npc.clearLookTarget()       // отменить
```

### Мгновенный, потиковый поворот: `lookAtNow`

`lookAtNow` отличается от остальной части этой страницы. Он сразу поворачивает NPC на указанный угол, один раз, и возвращает, достаточно ли близко NPC уже повёрнут к цели, чтобы считать, что он "смотрит" на неё:

```kotlin
val facing: Boolean = npc.lookAtNow(player, maxAngularSpeed = 360f)
```

Есть два способа использовать `lookAtNow`: вызывать функцию каждый тик, например из обработчика `onUpdate { ... }` в [node-скрипте](/docs/hollowengine/scripting/node), с небольшим `maxAngularSpeed` для плавного поворота и слежения за движущейся целью или вызвать её один раз с большим `maxAngularSpeed`, чтобы мгновенно установить угол поворота NPC.

## Использование блока

```kotlin
npc.useBlock(pos(10, 64, 10))
```

Ведёт NPC к блоку, разворачивает его лицом к блоку и использует блок основной рукой - полезно для рычагов, кнопок и других интерактивных блоков (блоки могут использовать только игроки, так что не факт, что оно сработает на чём-то из модов). Дополнительные параметры:

```kotlin
npc.useBlock(pos(10, 64, 10), hand = InteractionHand.OFF_HAND, reach = 4.0)
```

`useBlockNow(pos, ...)` делает то же самое мгновенно, без ходьбы и ожидания, и срабатывает только если NPC уже находится в пределах `reach`. `startUseBlock(...)` - фоновая форма.

:::warning
`useBlock`, `destroyBlock` и `interact` сначала ведут NPC к цели, и для этого используют тот же канал `MOVEMENT`, что и `move`/`startMove`. Если NPC уже куда-то шёл в фоне, это движение будет заменено - действует то же правило из [Действий и параллельности](/docs/hollowengine/scripting/npc/actions).
:::

## Разрушение блока

```kotlin
npc.destroyBlock(pos(10, 64, 10))
```

Ведёт NPC к блоку, разворачивает лицом к нему и ломает блок, как это сделал бы fake player (по умолчанию учитывая требования к инструменту). Установи `requireCorrectTool = false`, чтобы NPC мог ломать блоки без подходящего инструмента. `startDestroyBlock(...)` - фоновая форма.

## Взаимодействие с сущностью

```kotlin
npc.interact(playerRef)
```

Ведёт NPC к целевой сущности и взаимодействует с ней указанной рукой (по сути, аналог правого клика по ней). `interactNow(target, ...)` делает то же самое мгновенно, если цель уже в радиусе досягаемости, без ходьбы. `startInteract(...)` - фоновая форма.

```kotlin
val result: InteractionResult = npc.interactNow(someEntity)
```
