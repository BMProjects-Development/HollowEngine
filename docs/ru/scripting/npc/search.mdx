<center><h1>Поиск сущностей и предметов</h1></center>

*Спросите у NPC, что находится рядом: игроков, других NPC, любую сущность или выпавшие предметы.*

Примеры ниже - фрагменты серверного `.node.kts`. `npc` - персонаж, полученный через `npc(...)` или `this@NpcEntity` у [прикреплённой ноды](/docs/hollowengine/scripting/node). `player` в примерах - серверный игрок из обработчика взаимодействия. Вызовы, которые ждут завершения, помещайте в `onStart`, `onInteract` или `@State suspend fun`.

## Вспомогательные функции

Для частых задач используйте готовые функции. Они возвращают список ссылок, а поиск одного ближайшего предмета может вернуть `null`:

```kotlin
val nearbyPlayers = npc.findPlayers(radius = 10.0) // Найти игроков рядом
val nearbyNpcs = npc.findNpcs(radius = 10.0) { other -> other.uuid != npc.uuid } // Найти нпс рядом + фильтр (убирает ищущего нпс)
val nearestBread = npc.findNearestItem(itemFilter(item("minecraft:bread")), radius = 8.0) // Найти предметы рядом
```

| Функция | Возвращает |
|---------|------------|
| `findPlayers(radius, filter)` | Игроков рядом с NPC, ближайшего первым. |
| `findNpcs(radius, filter)` | Других NPC рядом, ближайшего первым. |
| `findItems(filter, radius, limit)` | Выпавшие предметы, подходящие под [`ItemFilter`](/docs/hollowengine/scripting/npc/inventory), ближайший первым. |
| `findNearestItem(filter, radius)` | Только один, ближайший подходящий выпавший предмет, либо `null`, если такого нет. |

Каждый результат - это `Ref<T>`, тот же тип ссылки, что используется для [запоминания сущностей в сюжете](/docs/hollowengine/scripting/node/states#story-logic), а не сырая сущность. Это сделано намеренно: к моменту, когда результат реально понадобится, сущность может уже переместиться в другой мир или даже деспавниться, а `Ref` умеет безопасно дождаться её и заново найти.

```kotlin
val playerRef = npc.findPlayers(radius = 10.0).firstOrNull() ?: return
val player = playerRef.resolve() // безопасно получить живую сущность
```

## Построение своего поиска

Для чего-то более специфичного, чем "игроки рядом", можно использовать `entityQuery<T> { ... }`, чтобы точно описать, что нужно найти, а затем передать это в `findEntities(...)` или `findNearestEntity(...)`:

```kotlin
import net.minecraft.world.entity.monster.Zombie

val query = entityQuery<Zombie> {
    radius = 24.0
    aliveOnly = true
    visibleOnly = true       // только сущности, который NPC действительно видит
    limit = 5
    sort = EntityQuerySort.NEAREST
    filter { zombie -> !zombie.isBaby }
}

val zombies: List<Ref<Zombie>> = npc.findEntities(query)
val closest: Ref<Zombie>? = npc.findNearestEntity(query)
```

| Настройка | По умолчанию | Значение |
|-----------|--------------|----------|
| `radius` | `16.0` | Радиус поиска вокруг NPC. |
| `aliveOnly` | `true` | Пропускать мёртвых/удалённых сущностей. |
| `visibleOnly` | `false` | Включать только сущностей, до которых у NPC есть прямая линия видимости. |
| `limit` | без ограничений | Максимальное число результатов. |
| `sort` | `EntityQuerySort.NEAREST` | `NEAREST`, `FARTHEST` или `NONE` (без определённого порядка, самый быстрый вариант). |
| `filter { ... }` | нет | Можно добавить сколько угодно дополнительных условий; `filter { ... }` можно вызывать несколько раз, сущность должна пройти их все. |

`findNearestEntity(query)` - это просто сокращение, которое принудительно задаёт `limit = 1` и `sort = NEAREST`, так что вместо списка возвращает один `Ref<T>?`.

## О `Ref<T>` и типах

В `findEntities<T>` и `entityRef<T>(uuid)` укажите ожидаемый тип сущности. Например, `<Zombie>` означает «ищем зомби»: подсказки редактора будут показывать его свойства. Если по UUID найдётся сущность другого типа, `resolve()` завершится ошибкой.

`Ref` помогает снова найти сущность после ожидания или загрузки чанка, но не воскрешает удалённого персонажа. Учитывайте отмену сценария, если цель уже не может появиться.
