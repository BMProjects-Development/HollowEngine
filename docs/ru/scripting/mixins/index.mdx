<center><h1>Mixin-скрипты</h1></center>

*Меняйте поведение методов Minecraft без отдельного мода и перезапуска после каждой правки логики.*

Mixin-скрипт - это Kotlin-файл с постфиксом `.mixin.kts`. Он объявляет точки, в которые HollowEngine должен встроить код до загрузки классов игры, а затем связывает их с обычными Kotlin-обработчиками.

Mixin-скрипты подходят, когда игрового события недостаточно: нужно выполнить код в середине конкретного метода, заменить вызов, изменить возвращаемое значение или заменить метод целиком. Такое вмешательство зависит от внутреннего устройства Minecraft и других модов, поэтому сначала стоит попробовать обычные [события](/docs/hollowengine/scripting/events), если их достаточно для решения вашей задачи.

## Первый mixin

Создайте в `hollowengine/scripts` файл с окончанием `.mixin.kts`, например `jump.mixin.kts`:

```kotlin
import net.minecraft.network.chat.Component
import net.minecraft.world.entity.player.Player

mixin<Player> {
    method("jumpFromGround") {
        after {
            if (!self.level().isClientSide) {
                self.displayClientMessage(Component.literal("Игрок прыгнул"), true)
            }
        }
    }
}
```

`mixin<Player>` выбирает класс, `method("jumpFromGround")` - объявленный в нём метод, а `after` запускает тело перед каждым выходом из метода. Внутри тела `self` имеет тип `Player`.

Для компиляции нового или изменённого mixin-скрипта нужен актуальный аддон-компилятор Kotlin. Экспортированный аддон может содержать уже скомпилированные скрипты, поэтому конечным игрокам компилятор не обязателен.

:::warning
Mixin можно добавить только в метод, объявленный самим целевым классом, а не переопределённый. Если метод унаследован, укажите в `mixin<...>` класс, в котором он действительно объявлен.
:::

## Когда применяются изменения

У mixin-скрипта отдельно живут **объявления** точек внедрения и само **тело** обработчика, но некоторые части скрипта можно обновить даже без перезапуска игры:

| Что изменилось                                                            | Когда применяется                                                                          |
|---------------------------------------------------------------------------|--------------------------------------------------------------------------------------------|
| целевой класс или метод, вид внедрения, `at`, `ordinal`                   | после перезапуска игры                                                                     |
| код внутри `before { ... }`, `after { ... }`, `code { ... }` и других тел | сразу после повторного запуска скрипта командой                                            |
| добавлена новая декларация                                                | после перезапуска игры                                                                     |
| декларация удалена                                                        | её тело отключается при повторном запуске, окончательно вставка исчезает после перезапуска |

Чтобы заменить тела уже применённых mixin-ов, выполните:

```text
/hollowengine scripting run scripts/examples/mixins/jump.mixin.kts
```

Команда сообщает, сколько тел заменено и сколько новых или изменённых деклараций ждут перезапуска. Скрипт при этом выполняется заново целиком, поэтому обновляются и значения, которые его обработчики захватывают из верхнего уровня.

Декларации читаются компилятором и должны состоять из констант. Например, так писать нельзя:

```kotlin
val targetMethod = "jumpFromGround"

mixin<Player> {
    method(targetMethod) { // Ошибка: имя должно быть строковой константой
        after { }
    }
}
```

Код внутри обработчика может быть обычным динамическим Kotlin-кодом.

## Операции над методом

Внутри `method("имя")` доступны операции, названные по своему результату:

| Операция                                           | Что делает                                                                              |
|----------------------------------------------------|-----------------------------------------------------------------------------------------|
| `before { }`                                       | выполняет тело в начале метода                                                          |
| `after { }`                                        | выполняет тело перед каждым `return`; у метода с результатом он доступен через `result` |
| `beforeCall<T>("name") { }`                        | выполняет тело перед вызовом указанного метода                                          |
| `afterCall<T>("name") { }`                         | выполняет тело после указанного вызова                                                  |
| `replaceCall<T>("name") { instance, args -> ... }` | заменяет вызов; `proceed()` вызывает оригинал                                           |
| `modifyCall<T, R>("name") { original -> ... }`     | заменяет значение, возвращённое вызовом                                                 |
| `returns<R> { original -> ... }`                   | заменяет результат целевого метода                                                      |
| `wrap { ... }`                                     | оборачивает весь метод; `proceed()` запускает оригинал                                  |

Тип `T` в операциях над вызовом указывает владельца вызываемого метода, а `R` - тип изменяемого значения:

```kotlin
mixin<Player> {
    method("jumpFromGround") {
        replaceCall<Player>("causeFoodExhaustion") { _, _ ->
            // proceed() не вызывается, поэтому прыжок не тратит сытость.
            null
        }
    }
}
```

Если один вызов встречается несколько раз, параметр `ordinal` выбирает нужный, начиная с нуля. Без `ordinal` обработчик применяется ко всем подходящим вызовам:

```kotlin
beforeCall<Player>("awardStat", ordinal = 1) {
    // Только второй вызов awardStat.
}
```

## Контекст обработчика

Обработчики получают контекст, зависящий от операции:

- `self` - объект, на котором выполняется целевой метод. У статического метода его нет.
- `args[index]` - аргументы целевого метода или оборачиваемого вызова. В `replaceCall` и `wrap` их можно изменить через `args[index] = value` перед `proceed()`; в обработчиках `inject` они доступны только для чтения.
- `cancel()` в `before`, `after`, `beforeCall`, `afterCall` и `inject` немедленно завершает метод без результата.
- `result` в тех же обработчиках задаёт результат и немедленно завершает метод. Читать его имеет смысл в точках `RETURN` и `TAIL`.
- `proceed()` в `replaceCall` и `wrap` выполняет оригинальный вызов или метод с текущими аргументами.
- `proceed(receiver, vararg arguments)` и `proceed(vararg arguments)` позволяют вызвать оригинал с другими значениями.

У обработчиков изменения значения исходное значение передаётся отдельным параметром:

```kotlin
mixin<LivingEntity> {
    modifyReturnValue<Float>("getJumpPower()F") {
        code { original ->
            if (self is Player) original * 1.5f else original
        }
    }
}
```

## Точные имена методов

Если у класса только один метод с таким именем, достаточно `"jumpFromGround"`. Для перегруженного метода укажите JVM-дескриптор:

```kotlin
method("hurt(Lnet/minecraft/world/damagesource/DamageSource;F)Z") {
    before { }
}

modifyReturnValue<Float>("getJumpPower()F") {
    code { original -> original * 1.5f }
}
```

Компилятор проверяет, что класс и метод существуют, вызов или поле действительно встречается в байткоде, `ordinal` попадает в допустимый диапазон, а тип изменяемого значения совпадает. Неоднозначное имя выдаст ошибку и предложит подходящие дескрипторы.

## Явные точки внедрения

Для более точного управления доступны операции, соответствующие Mixin и MixinExtras напрямую:

| Объявление                                                               | Назначение                                                 |
|--------------------------------------------------------------------------|------------------------------------------------------------|
| `inject(method) { at(...); code { } }`                                   | `@Inject` в указанную точку                                |
| `modifyReturnValue<R>(method) { code { original -> ... } }`              | `@ModifyReturnValue` результата метода                     |
| `modifyExpressionValue<R>(method) { at(...); code { original -> ... } }` | `@ModifyExpressionValue` результата вызова или чтения поля |
| `wrapOperation(method) { at(...); code { instance, args -> ... } }`      | `@WrapOperation` вокруг вызова                             |
| `wrapMethod(method) { code { ... } }`                                    | `@WrapMethod` вокруг всего метода                          |

Простые точки - `HEAD`, `RETURN` и `TAIL`. Вызов и чтение поля задаются функциями `call` и `field`:

```kotlin
inject("jumpFromGround") {
    at(call<Player>("awardStat", shift = Shift.AFTER))
    code {
        // Выполняется сразу после awardStat.
    }
}
```

У `call` и `field` также есть `ordinal`. Чтение поля задаётся как `field<Owner>("name")`. Если вызываемый метод перегружен, добавьте к его имени дескриптор так же, как для целевого метода.

:::advice
Для повседневных случаев предпочитайте `method { before/after/... }`: он короче и сразу показывает намерение. Явные операции полезны, когда нужна конкретная точка или прямое соответствие знакомой аннотации Mixin.
:::

## Клиент и сервер

По умолчанию mixin-скрипт применяется в каждой установленной копии игры: на физическом клиенте и на выделенном сервере. Для изменения клиентского класса добавьте в самое начало файла:

```kotlin
@file:ClientSide
```

Такой скрипт не компилируется и не применяется на выделенном сервере. Общий mixin-скрипт, от которого зависит одинаковая игровая логика, должен быть установлен и у игроков, и на сервере.

## Импорты и общий код

Mixin-скрипт поддерживает обычный [`@file:Import`](/docs/hollowengine/scripting/imports). Это удобно для состояния и функций, которые используются в обработчиках. Готовый пример находится в `hollowengine/scripts/examples/mixins/`: `jump.mixin.kts` импортирует общий `jump_stats.kts` и демонстрирует несколько механизмов сразу.

```kotlin
@file:Import("jump_stats.kts")

import net.minecraft.network.chat.Component
import net.minecraft.world.entity.LivingEntity
import net.minecraft.world.entity.player.Player
import ru.hollowhorizon.hollowengine.HollowEngine

mixin<Player> {
    method("jumpFromGround") {
        after {
            if (!self.level().isClientSide) {
                val count = countJump(self)
                self.displayClientMessage(Component.literal("Прыжок №$count"), true)
            }
        }

        beforeCall<Player>("awardStat") {
            if (!self.level().isClientSide) {
                HollowEngine.LOGGER.info("{} is about to get the jump stat", self.name.string)
            }
        }

        replaceCall<Player>("causeFoodExhaustion") { _, _ -> null }
    }
}

mixin<LivingEntity> {
    modifyReturnValue<Float>("getJumpPower()F") {
        code { original -> if (self is Player) original * jumpBoost else original }
    }
}
```

Соседний `jump_stats.kts` помечен `@file:SharedScript`, хранит число прыжков и `jumpBoost`. Изменение `jumpBoost` и повторный запуск `jump.mixin.kts` заменяют тела уже применённых mixin-ов без перезапуска игры.

:::warning
Mixin-скрипты чувствительны к версии Minecraft и изменениям других модов. После обновления проверяйте диагностику: имя метода, его дескриптор или набор вызовов внутри него могли измениться.
:::
