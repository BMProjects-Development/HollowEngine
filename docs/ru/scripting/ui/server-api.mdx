<center><h1>Управление UI с сервера</h1></center>

Откройте игроку экран, передайте ему текст задания и обработайте ответ. Сервер делает это через `UiSession` - объект открытого интерфейса. Сам экран заранее объявляется у клиента в `.ui.kts`; сервер обращается к нему по идентификатору.

Ниже показаны фрагменты серверного `.node.kts`: `player` - `ServerPlayer`, например `event.player as? ServerPlayer` в `onInteract`. Для этого типа добавьте `import net.minecraft.server.level.ServerPlayer`. Ключи данных на клиенте и сервере должны иметь одинаковые имена и типы; переменная из клиентского файла сама по себе серверу недоступна.

## Открытие экрана

```kotlin
val Title = dataKey<String>("title") { "Нет задания" }

val session = player.openUi("mypack:quest_log") {
    put(Title, "Пропавший груз")
    onEvent { payload ->
        if (payload.getString("action") == "accept") {
            player.sendSystemMessage("Задание принято".literal)
            close()
        }
    }
    onClose { println("Журнал заданий закрыт") }
}
```

`openUi` возвращает управление сразу и не приостанавливает скрипт. Клиент отправляет явные payload через `send { ... }` из UI-объявления.

## Оверлей

```kotlin
val Stamina = dataKey<Float>("stamina") { 1f }

val overlay = player.showOverlay("mypack:stamina") { put(Stamina, 1f) }
overlay.put(Stamina, 0.5f)
overlay.close()
```

У каждого игрока своя сессия. Если сервер показывает тот же id оверлея снова, клиент заменяет предыдущий.

## Состояние и патчи

Адаптивное объявление `surface` открывается через `player.openSurface("project:dialogue")`. Возвращается та же `UiSession`: обработчики событий, `put`, `update` и закрытие работают как у экрана. Клиент сам выбирает HUD или экран по данным сессии; см. [адаптивную поверхность](/docs/hollowengine/scripting/ui/ui-files).

`DataKey<T>` задаёт имя, сериализатор и необязательное значение по умолчанию. Тот же ключ читается в UI как `data[Key]`, а сервер записывает его через `put(Key, value)`.

```kotlin
@Serializable
data class Quest(val title: String, val progress: Int)

val CurrentQuest = dataKey<Quest>("quest") { Quest("Нет задания", 0) }

session.edit {
    put(CurrentQuest, Quest("Пропавший груз", 3))
    put(Title, "Задание обновлено")
}
```

`put` отправляет только изменённый ключ. `edit { }` объединяет несколько записей в один патч, а `remove(Key)` удаляет значение с обеих сторон. Чтения в UI подписываются на отдельные ключи, поэтому обновляется только зависящее содержимое.

## Жизненный цикл сессии

| API | Действие |
| --- | --- |
| `session.onEvent { payload -> }` | Получает payload от `send { }` |
| `session.onClose { }` | Запускается при закрытии игроком или сервером |
| `session.close()` | Закрывает одну UI-сессию |
| `player.closeUi()` | Закрывает все UI-сессии HollowEngine у игрока |
| `player.showOverlay(id)` | Открывает серверный оверлей |

Сессии принадлежат игроку и удаляются при отключении. Всегда проверяйте действия и значения из payload на сервере.

## Видимость HUD

```kotlin
player.hideHudLayers(VanillaHudLayers.CROSSHAIR, VanillaHudLayers.HOTBAR)
player.showAllHudLayers()
```

`hiddenHudLayers()` возвращает известный серверу набор, а `resendHiddenHudLayers()` повторно отправляет его клиенту, например после возрождения.
