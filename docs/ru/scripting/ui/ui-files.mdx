<center><h1>Файлы UI-скриптов</h1></center>

Создайте файл `.ui.kts` в `hollowengine/scripts`, чтобы добавить экран или оверлей. Вложенные папки тоже подходят. Клиент с установленным [компилятором Kotlin](/docs/hollowengine/addons/compiler) компилирует и запускает эти объявления при перезагрузке ресурсов.

Базовый класс скрипта: `UiScript`. Импорты UI, виджетов, layout, стилей, `DataKey` и HUD API добавляются автоматически.

## Экраны

`screen(id) { ... }` регистрирует экран. Его resource location затем использует сервер.

```kotlin
screen("mypack:settings") {
    title = "Настройки"
    closeOnEscape = true
    pausesGame = false
    content {
        Column(modifier = Modifier.padding(12.px).gap(8.px)) {
            Text("Настройки")
            Checkbox(checked = data[ShowHints], onCheckedChange = { checked ->
                send { putBoolean("showHints", checked) }
            })
        }
    }
}
```

По умолчанию `title` равен пути id, `closeOnEscape` равен `true`, а `pausesGame` равен `false`. Включайте `rebuildEveryFrame = true` только для содержимого, которое читает состояние клиента в каждом кадре.

## Замена существующих экранов

`override(...)` заставляет экран из скрипта заменить собой ванильный или модовый: как только игра открывает искомый экран, движок заменяет его на ваш.

```kotlin
import net.minecraft.client.gui.screens.TitleScreen

screen("mypack:main_menu") {
    override(TitleScreen::class)
    content { MainMenu() }
}
```

Замена происходит на клиенте и не требует сервера, поэтому работает и в главном меню, до захода в мир. Это же означает, что у заменяющего экрана нет сессии: `data` пуста и отвечает только значениями по умолчанию своих ключей, а `send { }` никуда не уходит. В распоряжении остаётся только клиентское состояние и `mc`.

`override(target, subclasses = true)` расширяет совпадение на всё, что наследует `target`, - для экрана, от которого унаследовался мод. Экран, который скрипт не может импортировать, указывается именем класса:

```kotlin
override("com.example.mod.FancyScreen")
```

Один ваш экран может заменять несколько ванильных экранов. `LocalReplacedScreen` хранит заменённый экран, который вы можете уточнить сами:

```kotlin
screen("mypack:menus") {
    override(TitleScreen::class)
    override(PauseScreen::class)
    content {
        when (LocalReplacedScreen.current) {
            is TitleScreen -> MainMenu()
            else -> PauseMenu()
        }
    }
}
```

| Правило | Что значит |
| --- | --- |
| Побеждает последний скрипт | Если один класс заменяют два скрипта, его забирает загруженный позже, и в лог пишется предупреждение |
| Экраны движка не заменяются | Собственные Compose-экраны HollowUi пропускаются, поэтому широкий `override` не проглотит интерфейс движка |
| Перезагрузка пересобирает открытую замену | Экран пересобирается из нового скрипта; если замены больше нет, экран закрывается |

К моменту подмены заменяемый экран уже отсоединён, поэтому экраны с контейнером (инвентарь и всё остальное, что стоит на меню) пока не поддерживаются: их меню закрывается вместе с ними.

## HUD-оверлеи

`overlay(id) { ... }` регистрирует HUD-слой. Он может управляться сервером или быть полностью клиентским.

```kotlin
overlay("mypack:stamina") {
    anchor(before("experience_bar"))
    autoShow = true
    content {
        val value = data[Stamina].coerceIn(0f, 1f)
        Box(modifier = Modifier.size((182f * value).px, 5.px).background(UiColor(0.3f, 0.8f, 1f)))
    }
}
```

| Параметр            | По умолчанию        | Значение                                                   |
|---------------------|---------------------|------------------------------------------------------------|
| `anchor(...)`       | `after("hotbar")`   | Где рисуется оверлей, подробнее ниже                       |
| `autoShow`          | `false`             | Показывать сразу после перезагрузки; для клиентского HUD   |
| `input`             | `OverlayInput.NONE` | `NONE` для HUD без ввода, `INTERACTIVE` для получения ввода |
| `rebuildEveryFrame` | `false`             | Перекомпоновывать каждый кадр; только когда это необходимо |

`interactive()` сокращает запись `input = OverlayInput.INTERACTIVE`. Во время игры интерактивный оверлей использует центр экрана, пока не получит событие указателя.

### Где рисуется оверлей

`anchor(...)` принимает одно или несколько мест в порядке приоритета:

| Место                               | Значение                                                                                                         |
|-------------------------------------|------------------------------------------------------------------------------------------------------------------|
| `after("слой")`, `before("слой")`   | В HUD после или до слоя vanilla. Допустимы короткие имена, например `crosshair`, `chat` и `experience_bar`       |
| `over(КлассЭкрана::class)`          | Поверх открытого экрана этого класса или его наследников. С `subclasses = false` подойдёт только сам класс       |
| `over("binary.class.Name")`         | То же для класса экрана, который скрипт не может импортировать                                                   |
| `over()`                            | Поверх любого открытого экрана                                                                                   |

Каждому `over` можно передать уровень. `ScreenLevel.BACKGROUND` рисует поверх затемнённого мира, но под самим экраном. `ScreenLevel.CONTENT` (по умолчанию) рисует поверх экрана, но под его подсказками. `ScreenLevel.TOP` рисует поверх всего.

Например, реплика диалога над сообщениями чата, по которой можно кликнуть в открытом чате:

```kotlin
import net.minecraft.client.gui.screens.ChatScreen

overlay("mypack:line") {
    anchor(after("chat"), over(ChatScreen::class))
    interactive()
    content { Text("Кликните по мне в чате") }
}
```

Пока экран закрыт, оверлей стоит в HUD на месте `after` или `before`. Когда открывается экран, срабатывает первый подходящий `over`: оверлей рисуется поверх этого экрана и получает настоящий курсор. Если ни один `over` не подошёл, оверлей остаётся в HUD под экраном и ввода не получает. Место в HUD у оверлея может быть только одно. Оверлей только с `over` скрыт, пока не открыт подходящий экран.

На уровне `BACKGROUND` клавиатура остаётся у экрана. Кликнуть по оверлею можно только там, где у экрана нет своего виджета или панели контейнера.

## Адаптивная поверхность

`surface(id)` подходит для интерфейса, который иногда является HUD, а иногда - полноценным экраном. Например, диалог без вариантов ответа можно показывать поверх игры, а при выборе ответа включать экран с курсором. Объявление использует один `content` и одну сессию:

```kotlin
import ru.hollowhorizon.hollowengine.common.ui.net.UiSurfaceKind

val Choosing = dataKey<Boolean>("choosing") { false }

surface("project:dialogue") {
    anchor(after("hotbar"))
    mode { state ->
        if (state[Choosing]) UiSurfaceKind.SCREEN else UiSurfaceKind.OVERLAY
    }
    content {
        Text(if (data[Choosing]) "Выберите ответ" else "Рассказ продолжается")
    }
}
```

Сервер открывает её через `player.openSurface("project:dialogue")`, а `session.put(Choosing, true)` меняет режим без открытия новой сессии и потери её данных. Для панели на модели используйте отдельное объявление [panel](/docs/hollowengine/scripting/ui/world-panels).

У экранов `guiScale = UiGuiScale.Inherit` по умолчанию следует настройкам игры; `guiScale(3)` задаёт собственный масштаб, `guiScale(0)` выбирает автоматический. У экранов, оверлеев и адаптивных поверхностей `exitDuration` задаёт время сохранения интерфейса для анимации закрытия в миллисекундах. При закрытии движок выставляет состояние HSS `:closing`, по которому можно запустить анимацию исчезновения.

## Kotlin-композиция

`content { }` является композаблом с получателем `UiScope`. В нём можно вызывать композаблы, читать `data`, вызывать `send { }` и `close()`. Общие части UI выносите в Kotlin-функции:

```kotlin
@Composable
fun UiScope.Action(id: String, label: String, action: String) {
    Box(id = id, modifier = Modifier.padding(6.px).input(hoverable = true, clickable = true).onClick { send { putString("action", action) } }) {
        Text(label)
    }
}
```

Механизма XML-импортов больше нет: переиспользуйте Kotlin-функции, файлы и обычные импорты Kotlin.
