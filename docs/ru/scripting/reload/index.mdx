# Перезапускаемые скрипты

Перезагружаемый скрипт - это файл с постфиксом `*.reload.kts`. По нему движок понимает тип скрипта, доступные переменные и функции.
В основном он нужен, чтобы подписываться на события и выполнять свою логику при их срабатывании.

Скрипт перезапускается целиком: при каждом перезапуске движок снимает все обработчики и корутины прошлого запуска и выполняет файл заново. Поэтому после правки не нужно перезаходить в игру.

## Серверные и клиентские скрипты

Каждый перезагружаемый скрипт работает на одной стороне. Сторону задаёт аннотация в самом начале файла:

| Аннотация                   | Где выполняется                                  | Когда перезапускается                                    |
|-----------------------------|--------------------------------------------------|----------------------------------------------------------|
| нет или `@file:ServerSide`  | на сервере (и на встроенном сервере одиночной игры) | при открытии мира и по `/reload`                         |
| `@file:ClientSide`          | только в игре у игрока, никогда на выделенном сервере | при запуске игры, по `F3 + T` и при смене ресурспака |

Серверные скрипты отвечают за игровую логику: игроков, сущностей, блоки, команды. Клиентские - за то, что видит и слышит конкретный игрок: HUD, экраны, рендер, клавиши.

```kotlin
@file:ClientSide

import ru.hollowhorizon.hollowengine.common.events.client.render.RenderHudEvent

@SubscribeEvent
fun onHud(event: RenderHudEvent) {
    event.guiGraphics.drawString(minecraft.font, "Привет!", 4, 4, 0xFFFFFF)
}
```

![Клиентский скрипт выводит текст на HUD](/hollowengine/pictures/ide/client-reload-script.webp)

:::warning
Выделенный сервер не компилирует клиентские скрипты вовсе, а в сетевой игре клиент берёт скрипты только из своей папки `hollowengine/scripts`. Клиентские скрипты должны лежать у игроков, например в сборке.
:::

Одному файлу нельзя указать обе аннотации. Если серверному и клиентскому скрипту нужен общий код, вынесите его в обычный `.kts` и подключите в оба через [`@Import`](/docs/hollowengine/scripting/imports).

## Доступные переменные

```kotlin
resources // ResourceManager: датапаки на сервере, ресурспаки на клиенте

// Только в серверных скриптах
recipeManager // RecipeManager - для работы с рецептами

// Только в клиентских скриптах
minecraft // Minecraft - клиент игры
```

:::advice
Серверный скрипт запускается ещё до создания сервера, во время загрузки датапаков мира, поэтому переменной `server` в нём нет. Внутри обработчиков сервер почти всегда можно получить из самого события: `event.player.server`, `event.level.server`, `event.server`.
:::

## Подписываемся на событие

Для подписки нужно создать функцию, принимающую событие, и добавить к ней аннотацию `@SubscribeEvent`:

```kotlin
@SubscribeEvent
fun onPlayerJoin(event: PlayerEvent.Join) {

}
```

Название функции может быть любым, главное добавить аннотацию и параметр с нужным событием.

Скрипт получает события только своей стороны. Если событие происходит только на другой стороне (например, клиентский `RenderHudEvent` в серверном скрипте), движок сообщит об ошибке в логе при подписке, вместо того чтобы молча никогда не вызвать обработчик. У каждого события в [списке событий](/docs/hollowengine/scripting/events) указано, на какой стороне оно срабатывает.

:::advice
Иногда вам может потребоваться, чтобы ваше событие срабатывало раньше других (особенно если его нужно отменить).
Для этого можно поменять порядок его обработчика, для этого передайте приоритет в аннотацию: `@SubscribeEvent(10)`.
По умолчанию приоритет нулевой.
:::

## Корутины

Скрипт сам является `CoroutineScope`, поэтому в нём можно сразу вызывать `launch` и `delay`. Корутины выполняются на потоке своей стороны и отменяются при перезапуске скрипта, так что после `/reload` старые задачи не продолжат работу.

```kotlin
import ru.hollowhorizon.hollowengine.common.events.entity.player.PlayerEvent
import ru.hollowhorizon.hollowengine.common.scripting.story.functions.player.send

@SubscribeEvent
fun onPlayerJoin(event: PlayerEvent.Join) {
    launch {
        delay(3000) // 3 секунды
        event.player.send("Привет, ${event.player.name.string}!")
    }
}
```

## Команды

Серверный скрипт может добавлять свои команды через `RegisterCommandsEvent`. Движок вызывает его уже после запуска скриптов, так что команды появляются сразу при открытии мира, а после `/reload` обновляются вместе со скриптом.

```kotlin
import net.minecraft.commands.Commands
import ru.hollowhorizon.hollowengine.common.events.registry.RegisterCommandsEvent

@SubscribeEvent
fun onCommands(event: RegisterCommandsEvent) {
    event.dispatcher.register(
        Commands.literal("hello").executes { context ->
            context.source.sendSuccess({ "Привет!".literal }, false)
            1
        }
    )
}
```

## Применение изменений

- Серверный скрипт: `/reload`, **Файл > Перезагрузить серверные ресурсы** в IDE или повторное открытие мира.
- Клиентский скрипт: `F3 + T` или **Файл > Перезагрузить клиентские ресурсы**.

При включении или отключении аддона движок сам перезагружает датапаки всех запущенных серверов, поэтому скрипты и команды аддона появляются и исчезают без ручного `/reload`.

Список доступных событий и их описание вы можете найти в этом [разделе](/docs/hollowengine/scripting/events).
