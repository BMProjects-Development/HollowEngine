<center><h1>Controllers and Progress</h1></center>

*Start sessions, bind characters, localise stories, and preserve progress.*

![Dialogue controllers](/hollowengine/titles/dialogues/control.webp)

## Participants and characters

```kotlin
val dialogue = DialogueController("project:stories/gate.story")

val result = dialogue.start(player, companion) {
    character("Guard", DialogueCharacter.of(guard))
    character("Merchant", DialogueCharacter.of("Travelling Merchant"))
    put("money", 35)
    put("hasPass", false)
}
```

The first participant is available as `player`. A string character can speak, but entity commands require `DialogueCharacter.of(entity)`.

One controller represents one session and cannot run twice simultaneously. Pass several players to one `start` call for a shared scene. Create separate controllers for independent conversations.

`start` returns a `DialogueResult`. `launchIn(scope, players...)` starts without blocking the caller. `startHeadless()` runs world logic without participants.

## Variables at start

Use `put` for strings, numbers, and booleans, or `variables` for direct access:

```kotlin
dialogue.start(player) {
    put("name", player.name.string)
    put("money", 35)
    put("hasPass", false)
    variables { this["visits"] = StoryNumber(3f) }
}
```

Values remain until overwritten, the story finishes normally, or `reset()` is called.

## Multiplayer voting

By default, a menu waits indefinitely for every online participant. Configure a timeout in the builder:

```kotlin
val dialogue = DialogueController("project:stories/council.story") {
    votePolicy = VotePolicy(timeoutMillis = 15_000, abstainOnTimeout = true)
}
```

Most votes wins, ties are random, and the first option wins when nobody voted. Inspect stable choice `id` values through `onChoice` or `DialogueEvent.Chosen`.

## Localisation

Translations are complete story files:

```text
stories/gate.story
stories/gate.ru_ru.story
```

```kotlin
val dialogue = DialogueController("project:stories/gate.story") {
    locale = "ru_ru"
}
```

The engine tries the localised file first and falls back to the base story. Keep choice ids stable between translations.

## Checkpoints

The controller keeps its label, call stack, variables, named tracks, and function state. Normal completion clears them. Leaving players, cancellation, and failures keep the checkpoint.

- `save(key, tag)` writes progress into a `CompoundTag`.
- `load(key, tag)` restores it before the next `start`.
- `reset()` discards progress and variables.
- `checkpoint()` returns the current snapshot.

```kotlin
dialogue.onCheckpointRequest { controller ->
    controller.save("gate-dialogue", persistentTag)
}

dialogue.load("gate-dialogue", persistentTag)
dialogue.start(player) {
    character("Guard", DialogueCharacter.of(guard))
}
```

Custom commands call `checkpoint()` on `StoryCallContext` to trigger the persistence callback immediately. Checkpoints use a label plus an offset, so edits above a stable label do not move the resume point.

## Events and editor support

Controllers provide `onDialogStart`, `onDialogEnd`, `onChoice`, `onStart(tag)`, and `onEnd(tag)`. Global handlers use `DialogueEvent.Started`, `Ended`, `Chosen`, `ActionStarted`, and `ActionEnded`.

The built-in IDE highlights `.story`, checks indentation and signatures, completes commands and arguments, and navigates from `@jump` or `@call` to targets.
