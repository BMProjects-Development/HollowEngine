<center><h1>Custom Story Commands</h1></center>

*Expose reusable Kotlin actions to `.story` files.*

![Custom dialogue commands](/hollowengine/titles/dialogues/custom-commands.webp)

A command can be global or local. Both paths use `StoryFunctionRegistry`, so signatures, completion, and runtime argument binding behave identically.

## Global commands from reload.kts

Use `RegisterStoryFunctionsEvent` when every dialogue should see a command:

```kotlin
import net.minecraft.network.chat.Component
import ru.hollowhorizon.hollowengine.common.dialogue.RegisterStoryFunctionsEvent
import ru.hollowhorizon.hollowengine.common.dialogue.lang.string

@SubscribeEvent
fun registerDialogueCommands(event: RegisterStoryFunctionsEvent) {
    event.functions.unregister("announce")
    event.functions.add("announce", string("text")) { args ->
        val message = Component.literal(args.string("text"))
        players.forEach { it.sendSystemMessage(message) }
    }
}
```

```story
@announce "The gates are closing"
```

The event is posted again when story functions reload. The handler must be idempotent, so call `unregister` once before adding every overload owned by that script. Use a distinctive command name to avoid removing another script's overloads.

## Commands local to one controller

```kotlin
val gateDialogue = DialogueController("project:stories/gate.story") {
    functions.add("guard-log", string("text")) { args ->
        server.sendSystemMessage(Component.literal("[Gate] ${args.string("text")}"))
    }
}
```

Local functions live in a child registry. They inherit every global command, but do not leak into other controllers.

## Typed registration

For one to three required parameters, Kotlin types can describe the signature:

```kotlin
functions.add<String, Float>(
    "change-reputation",
    params = listOf("faction", "amount"),
) { faction, amount ->
    updateReputation(players, faction, amount)
}
```

| Kotlin type | Story type |
| --- | --- |
| `String` | Text |
| `Float`, `Int`, `Double` | Number |
| `Long` | Duration in milliseconds |
| `Boolean` | Boolean |
| `List<*>` | List |

Use full descriptors when parameters are optional, have defaults, need actor resolution, or exceed three arguments.

## Full signatures and defaults

```kotlin
import kotlinx.coroutines.delay
import net.minecraft.network.chat.Component
import ru.hollowhorizon.hollowengine.common.dialogue.lang.number
import ru.hollowhorizon.hollowengine.common.dialogue.lang.string
import kotlin.time.Duration.Companion.milliseconds

functions.add(
    "notify",
    string("text"),
    number("time", default = 2_000f),
) { args ->
    val message = Component.literal(args.string("text"))
    players.forEach { it.sendSystemMessage(message) }
    delay(args.millis("time").milliseconds)
}
```

Descriptors are `string`, `number`, `boolean`, `list`, `actor`, and `any`. Most accept `optional = true`; `string`, `number`, and `boolean` also support a default.

`StoryArguments` provides `string`, `number`, `int`, `bool`, `list`, `millis`, `actor`, `entity`, and `vec3`, plus nullable variants for omitted values. Several overloads may share a name when their parameter name lists differ.

## Command context

The handler is a suspending extension on `StoryCallContext`:

- `session` exposes variables and characters.
- `server` exposes server and world APIs.
- `players` contains online participants.
- `state` is a `CompoundTag` checkpoint owned by the current call.
- `checkpoint()` requests immediate persistence after changing `state`.

Commands may call suspending APIs. An exception ends the dialogue with `DialogueResult.Failed` and keeps its checkpoint.

## Restart-safe side effects

A statement can run again after a server stop. Record completed side effects when duplication would be harmful:

```kotlin
functions.add("grant-key") { _ ->
    if (!state.getBoolean("granted")) {
        players.forEach(::grantGateKey)
        state.putBoolean("granted", true)
        checkpoint()
    }
}
```

The call state is removed after successful completion.

## Tagged actions

Every command accepts the reserved `tag=` argument:

```story
@notify "Chapter started" tag=chapter-start
```

```kotlin
gateDialogue.onStart("chapter-start") { event ->
    println("Started ${event.function}")
}

gateDialogue.onEnd("chapter-start") { event ->
    println("Finished with ${event.reason}")
}
```

Global listeners can use `DialogueEvent.ActionStarted` and `DialogueEvent.ActionEnded`.
