<center><h1>UI Examples</h1></center>

Build a confirmation screen, a HUD hint, and a window that waits for a reply. Store client declarations in `.ui.kts` and server actions in `.node.kts`. Each example explains where its parts belong.

## Server-driven confirmation screen

`hollowengine/scripts/confirm.ui.kts`:

```kotlin
val Message = dataKey<String>("message") { "Are you sure?" }

screen("mypack:confirm") {
    title = "Confirmation"
    content {
        Column(modifier = Modifier.padding(16.px).gap(12.px)) {
            Text(data[Message])
            Row(modifier = Modifier.gap(8.px)) {
                Box(id = "confirm-accept", modifier = Modifier.input(hoverable = true, clickable = true).onClick { send { putString("action", "accept") } }) { Text("Yes") }
                Box(id = "confirm-cancel", modifier = Modifier.input(hoverable = true, clickable = true).onClick { send { putString("action", "cancel") } }) { Text("No") }
            }
        }
    }
}
```

Create `hollowengine/scripts/confirm.node.kts` and attach it to an NPC. Load `confirm.ui.kts` on the client first by pressing `F3 + T`. Declare `Message` on the server with the same name and type:

```kotlin
@file:Attach(NpcEntity::class)

import net.minecraft.server.level.ServerPlayer

val Message = dataKey<String>("message") { "Are you sure?" }

onInteract { event ->
    val player = event.player as? ServerPlayer ?: return@onInteract
    player.openUi("mypack:confirm") {
        put(Message, "Remove one stone from your inventory?")
        onEvent { payload ->
            when (payload.getString("action")) {
                "accept" -> {
                    player.takeItems(itemFilter(item("minecraft:stone")), 1)
                    close()
                }
                "cancel" -> close()
            }
        }
    }
}
```

Right-click to open confirmation. “Yes” removes up to one stone if present; “No” and Escape close the screen without removing it. Each player gets a separate session. Unknown events are ignored.

## Client-owned HUD hint

```kotlin
val Hint = dataKey<String>("hint") { "" }

overlay("mypack:block_hint") {
    anchor = "crosshair"
    placement = HudPlacement.AFTER
    autoShow = true
    content {
        data.find(Hint)?.takeIf(String::isNotBlank)?.let { hint ->
            Box(modifier = Modifier.padding(4.px).background(UiColor(0f, 0f, 0f, 0.55f))) { Text(hint) }
        }
    }
}
```

Because this overlay is auto-shown and never calls `send`, it remains client-only. A server-owned version uses `player.showOverlay("mypack:block_hint")` and `UiSession.put(Hint, value)` instead.

## Awaiting a choice from a suspend function

The UI API has no `ui.await(player)`. A screen can send several events, and `UiSession` manages its lifecycle. Use a coroutine adapter when the server needs one choice.

The UI declaration sends a choice:

```kotlin
screen("mypack:quest_choice") {
    title = "A visitor asks for help"
    content {
        Column(modifier = Modifier.padding(16.px).gap(8.px)) {
            Text("Will you accept the quest?")
            Box(id = "choice-accept", modifier = Modifier.input(hoverable = true, clickable = true).onClick { send { putString("choice", "accept") } }) { Text("Accept") }
            Box(id = "choice-decline", modifier = Modifier.input(hoverable = true, clickable = true).onClick { send { putString("choice", "decline") } }) { Text("Decline") }
        }
    }
}
```

In a server script, add these imports and adapter once:

```kotlin
import kotlin.coroutines.resume
import kotlinx.coroutines.suspendCancellableCoroutine
import net.minecraft.server.level.ServerPlayer

private enum class QuestChoice { ACCEPT, DECLINE }

private suspend fun ServerPlayer.chooseQuest(): QuestChoice? = suspendCancellableCoroutine { continuation ->
    var session: UiSession? = null

    fun finish(choice: QuestChoice?) {
        if (!continuation.isActive) return
        continuation.resume(choice)
        session?.close()
    }

    session = openUi("mypack:quest_choice") {
        onEvent { payload ->
            when (payload.getString("choice")) {
                "accept" -> finish(QuestChoice.ACCEPT)
                "decline" -> finish(QuestChoice.DECLINE)
            }
        }
        onClose { if (continuation.isActive) continuation.resume(null) }
    }
    continuation.invokeOnCancellation { session?.close() }
}
```

The calling suspend function can then handle the result directly. Escape and server-side closure return `null`. Cancelling the coroutine closes the session and cancels the wait:

```kotlin
when (player.chooseQuest()) {
    QuestChoice.ACCEPT -> println("Player accepted the quest")
    QuestChoice.DECLINE -> println("Player declined the quest")
    null -> println("Choice closed without a reply")
}
```

Validate every choice on the server. Unknown payloads leave the screen open.
