<center><h1>Animations and Transforms</h1></center>

Make a button grow smoothly on hover or give a hint a repeating motion. Configure transitions, keyframes, transforms, and filters in HSS or through Kotlin modifiers.

## Transitions

A transition changes a property smoothly. For example, hovering over a card gradually changes `scale` from its normal value to the value in `:hover`. Transitions also work with `:active` and `:selected`.

```css
.card { transitions: background 120ms ease-out, scale 120ms ease-out; }
.card:hover { background: #5F8CCD; scale: 1.04; }
```

The Kotlin equivalent is `Modifier.transition(UiTransition("scale", 120, TransitionEasing.EASE_OUT))`. Transitions belong on the base node, not inside the state rule.

## Keyframes

Use `@keyframes` for a repeating or staged animation:

```css
@keyframes attention {
    0%, 100% { translate-y: 0; }
    50% { translate-y: -3; }
}

.notification { animations: attention 700ms ease-in-out infinite; }
```

A keyframe may set one axis at a time (`translate-y`, `scale-x`, `rotate-z`) and leave the other two where the base style put them.

From Kotlin, start the same named animation explicitly:

```kotlin
Box(modifier = Modifier.animation("attention", durationMillis = 700, iterationCount = Float.POSITIVE_INFINITY)) {
    Text("New reward")
}
```

## 2D/3D transforms and filters

`translate`, `rotate`, `scale`, `perspective`, and `pivot` compose into a transform. HSS has the corresponding `translate`, `rotate`, `scale`, `perspective`, `transform-origin`, and `backface-visibility` properties. `filter` and `backdrop-filter` support blur, grayscale, and shader effects.

Animate only visible nodes and keep stable identities for list items. Use transitions, keyframes, or text effects for UI motion. `rebuildEveryFrame` recomposes the whole surface and is intended for content that reads per-frame game state.
