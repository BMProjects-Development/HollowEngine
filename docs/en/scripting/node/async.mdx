## Child states and `async`

Sometimes you need to run parallel logic: for example, an NPC walks to a point while the player reads a dialogue, or an animation plays in the background.
Use `async` inside the active state for that.

```kotlin
@State
suspend fun main() {
    async("ambient_animation") {
        while (true) {
            println("NPC looks around")
            wait(3.sec)
        }
    }

    println("The main dialogue continues")
    wait(5.sec)
    nextScene()
}

@State
suspend fun nextScene() {
    println("Moving to the next scene")
}
```

A child state receives its own `stateTag()` and is saved separately from the parent state. When the parent state finishes or transitions further, its active child tasks are canceled.

For long-lived background processes, use clear names such as `"ambient_animation"`, `"move_to_gate"`, or `"wait_for_player"`, because the name becomes the child context key in the save data.
