## Create a cutscene

1. Open **Windows > Cutscenes** and create a new cutscene.
2. Place the scene's origin (the **Origin** section) - **Move here** is the quick way.
3. Add keyframes with the capture button: the current camera pose, time of day, and weather are written onto the active layer of every property.
4. Set the duration and preview the result from the timeline.
5. Save the cutscene. A name such as `intro` is stored as `hollowengine/cutscenes/intro.dat`.
6. Start it for a player from a server script.

The tracks are evaluated on the receiving client. Camera, HUD, hand rendering, time of day, and weather
can be controlled locally while the cutscene is active. The server world is not changed, and the client's
previous time and weather are restored when the cutscene or preview stops.

## What the file holds?

Every coordinate is stored **relative to the scene's origin** - the point and yaw recorded with it. The
file describes the *shape* of the move; where that shape lands is decided by the script that plays it.

The origin fields move the whole scene. **Re-anchor** does the opposite: the scene stays where it is
and only the numbers it is measured against change.

Older cutscenes are migrated on load: the origin is placed on the first position key, the keys are
re-expressed relative to it, and the old easings become curves. Nothing moves on screen.

## Objects, properties and layers

The timeline animates **properties**. On the camera these are `Transform` (Translation, Rotation) and
`Lens` (FOV); `World / Environment` contains Time of Day and Weather. A property breaks down into
**channels**, and every channel owns its keys, so X can be retimed and shaped without dragging Y and Z along.

Time of Day is continuous and uses Minecraft's 24,000-tick day. When it is the only selected graph track,
the value axis is shown as a 24-hour clock. Weather is discrete (`Clear`, `Rain`, `Thunder`): it changes on
a key and is intentionally absent from the curve editor.

A property can carry several **layers**. A layer is a full set of curves plus how it folds into the
layers below it:

| Blending | What it does |
| --- | --- |
| **Override** | Replaces the value below. The first layer is always this - there is nothing under it. |
| **Add** | Adds on top: shakes, offsets, corrections. |
| **Subtract** | The inverse of Add. |
| **Multiply** | Scales; only offered where scaling means something. |

The `+` on a property row adds a layer and opens its settings: name, blend mode, weight, visibility and
lock. The gear on the property row opens the property's own settings - its **limits** (a minimum and
maximum per channel, applied after every layer has had its say) and the rotation basis. Clicking a layer
row makes it the active one, which is where captured poses are written.

Hiding a layer, a channel or a whole group takes its contribution out of the result, and the preview
shows that immediately.

### Rotation: Euler or quaternion

A rotation is held as **angles** (pitch/yaw/roll in degrees). That matters: a quaternion has no memory
of how it got where it is, so a camera turned four times by 90° would come back as 0/90/180/-90 with a
roll conjured out of the decomposition. A recorded angle keeps counting - 0, 90, 180, 270 - and a curve
across the ±180° seam no longer takes the long way round. The property settings can switch to the
**quaternion** basis (x/y/z/w); switching resamples the curves and resets handles.

## Curves

Interpolation *is* a **curve preset**. A preset writes real handles that can then be dragged; there is
no separate easing mode any more. Besides the cubic presets there is **Hold** (the value stays until
the next key) and **Linear**.

Presets live in the inspector and in the right-click menu on a key.

Handles are stored **relative to their own key**, so retiming a key or re-anchoring the scene leaves
them intact. The modes are:

- **Auto** - derived from the neighbouring keys and flattened at extrema, so the camera never
  overshoots past its own keys;
- **Mirrored** - the partner copies both direction and length;
- **Aligned** - the partner copies the direction and keeps its own length;
- **Free** - each handle moves on its own.

Dragging a handle mirrors by default; hold `Shift` to keep the opposite handle's length, `Ctrl` to move
only the handle under the cursor. A handle facing a straight segment is drawn faint - grabbing it is
what turns that segment into a spline.

### The curve editor

The **Dope sheet / Curves** buttons in the toolbar (or `Ctrl+Tab`) switch modes.

- Keyframes live on the channel rows alone: a property and a layer are folders. The carets unfold a
  property into layers and a layer into channels; every channel has its own colour and visibility toggle.
- The wheel scrolls time, `Ctrl` + wheel zooms time, `Shift` + wheel zooms the value axis and
  `Alt` + wheel pans it. The value axis glides on a spring rather than jumping.
- The middle **or right** mouse button drags the canvas, in time and in value. A right button that
  never moved opens the context menu instead, so one button does both.
- The left button on empty space draws a selection band; `Ctrl` or `Shift` adds to what is selected.
- `Ctrl` + dragging a key clones the selection and drags the copies, leaving the originals in place.
- `Ctrl+C` / `Ctrl+X` / `Ctrl+V` copy, cut and paste keys. A paste lands on the same channels with the
  earliest key on the playhead and the rest keeping their spacing.
- `F` frames the visible curves, `S` smooths the selection.
- Clicking a row in the track list picks **what the graph draws**; `Ctrl` adds to the pick and clicking
  the same row again gives the whole graph back. This is a separate thing from the eye: hiding a track
  also takes it out of the preview, and uncluttering a graph is no reason to change the shot.
- The track list on the left is resizable by its splitter and scrolls when names do not fit.

## Start and stop playback

```kotlin
player.playCutscene("intro")

// Repeat the sequence until it is stopped.
player.playCutscene("ambient_pan", loop = true)

player.stopCutscene()
```

`playCutscene` replaces the player's current cutscene. Use a path relative to `hollowengine/cutscenes`; the `.dat` extension is optional. `stopCutscene()` immediately returns the camera to normal gameplay.

### Where to put the scene

```kotlin
// Around a position - a structure corner, say. yaw turns the whole scene.
player.playCutsceneAt("chapter_1/arrival", structurePos, yaw = 90f)

// Around an NPC; the scene keeps up with them while they walk.
player.playCutsceneNear("chapter_1/greeting", npc, follow = true)

// Around the player themselves, wherever they are standing.
player.playCutsceneHere("ambient_pan", loop = true)
```

`rotate = false` keeps the scene's recorded facing and only moves it. If the entity cannot be found,
the cutscene falls back to where it was recorded.

## A simple scene trigger

```kotlin
@State
suspend fun onInteract(player: ServerPlayer) {
    player.playCutscene("chapter_1/arrival")
    player.send("Welcome to the valley.")
}
```

For a looping camera while the player is in an area, start it when they enter and call `stopCutscene()` when they leave. Do not start the same loop every tick: one start is enough.
