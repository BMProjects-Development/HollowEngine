*Model metadata, material names, and dressing an entity from a script.*

## What a model brings with it

A model file — `.gltf`, `.glb`, Blockbench `.geo.json`, or `.obj` — lives in the usual asset structure and is specified by its resource location:

```kotlin
val guide = npc(
    pos = pos(10.0, 64.0, 10.0),
    model = "project:models/entity/guide.gltf",
)
```

Everything else the engine needs to know about the model lives beside it, in a file with the same name plus `.hemeta`:

```text
assets/project/models/entity/
├─ guide.gltf
└─ guide.gltf.hemeta
```

`.hemeta` is a TOML config. Every field is optional, and a model with no `.hemeta` at all works exactly as before:

```toml
preload = true
frustum-culling = false
animation-controller = "project:models/entity/guide.animator"

[materials]
skin = "Body"
cape = "material_3"
```

| Field | Meaning |
|------|---------|
| `preload` | Loads the model when resources load rather than when it is first used. Useful for frequently used models. It is disabled by default so that models used only a few times in a pack or map do not take up resources. |
| `frustum-culling` | Allows the model to be culled outside the camera frustum. Enabled by default. Set it to `false` when GPU skinning or morph targets move vertices beyond the model's calculated bounds. This disables only frustum culling; the entity's distance culling still applies. |
| `animation-controller` | The animator the model uses by default, see the [Animator Editor](/docs/hollowengine/scripting/animator-editor). |
| `[materials]` | New names for the model's materials, see below. |

## Material names

Every surface of a model is a material: a base texture, a normal map, a specular map, and a tint colour. Scripts address them **by name**.

The name comes from the model file. glTF materials have the name given to them by the artist; unnamed materials become `material_0`, `material_1`, and so on, in file order. A Blockbench `.geo.json` model has one material, named `texture`.

This works, but the script has to know how each model was exported. The `[materials]` section removes that dependency by renaming materials when they load:

```toml
[materials]
skin = "material_0"
```

`skin` is the new name, and `material_0` is the name the material already has in the model file. There are several predefined names:

| Name | Meaning |
|-----|---------|
| `skin` | The main body texture. It is also the name used by a player's own skin. |
| `cape` | A cape, including a player's cape. |
| `elytra` | An elytra texture. |

The built-in NPC models already have `skin`, but not `cape` or `elytra`. The vanilla player model has all three, so you can replace them when needed.

## Dressing an entity

`entity.materials` is a map from material name to what should be there:

```kotlin
val guide = npc(pos(0, 64, 0), name = "Guide", model = "project:models/entity/guide.gltf")

guide.materials["skin"] = texture("project:textures/entity/guide_night.png")
guide.materials["skin"] = skin("Notch") // Notch's skin
guide.materials["cape"] = cape("Notch") // Notch's cape

guide.materials.reset("skin") // restore the model's texture
guide.materials.clear() // restore the entire model
```

### Sources

A value is not a texture path but a *source* describing where the appearance comes from:

| Source | What it gives |
|----------|----------|
| `texture(texture, normal, specular, color)` | Textures from a resource pack. All arguments except the first are optional; `color` is `#rrggbb` or `#aarrggbb` and tints the material. |
| `skin(player)` | A player's skin, by nickname or UUID. |
| `cape(player)` | Their cape. |
| `elytra(player)` | Their elytra texture. |

```kotlin
guide.materials["skin"] = texture(
    texture = "project:textures/entity/guide.png",
    normal = "project:textures/entity/guide_n.png",
    color = "#ffddaa",
)
```

:::advice
`skin("Notch")` fetches the profile of a player who is not currently on the server the first time it is used. While it downloads, the entity wears the model's default skin. In your projects, it is better to use ready-made skins from your resources instead of fetching skins by nickname.
:::

## Players

A player's skin changes the same way regardless of whether they have a custom model. Without a custom model, the vanilla one changes:

```kotlin
player.materials["skin"] = texture("project:textures/entity/disguise.png")
player.materials["cape"] = cape("Notch")
```

Skin shape (`wide`/`slim`) is **not** a material. To change the skin type, use:

```kotlin
player.arms = PlayerArms.SLIM
player.arms = null
```
