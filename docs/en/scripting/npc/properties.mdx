<center><h1>NPC and Entity Properties</h1></center>

Change an NPC’s name, health, and behavior through Minecraft properties and HollowEngine components. Below, you will find the available settings and ways to keep a reference to your character.

---

## Main difference from the old documentation

The `npc` variable holds an `NpcEntity` object. It inherits the capabilities of a `PathfinderMob`, a `LivingEntity`, and the base `Entity`. For example, use `health` to access its health and `position()` to read its position.

Older examples use dynamic fields such as `Text`, `Bool`, and `Position`. In Kotlin, use the properties and functions listed below.

That means:

- standard Kotlin properties generated from Minecraft Java getters/setters are available;
- Minecraft entity API methods are available;
- HollowEngine adds a few convenience properties and functions on top.

```kotlin
val npc = npc(pos(0, 64, 0), name = "Guide")

npc.setNameplate("New Guide")
npc.health = 20f

val id = npc.uuid
val position = npc.position()
val alive = npc.isAlive
```

## HollowEngine `NpcEntity` properties

| Property | Type | Read | Write |
|----------|------|------|-------|
| `npc.pickupDistance` | depends on `pickupReach` | Item pickup radius. | Read-only. |
| `npc.fakePlayer` | `ServerPlayer` | Fake player used for actions such as breaking blocks. | Read-only. |
| `npc.goals` | `GoalSelector` | NPC goal selector. | Modify through the goal selector API. |
| `npc.inventory` | `NpcInventory` | The NPC's own inventory, see [Inventory and Item Collection](/docs/hollowengine/scripting/npc/inventory). | Read-only reference, modify through its functions. |
| `npc.data` | `EntityData` | Saved custom data attached to the NPC, see [Custom Data](/docs/hollowengine/scripting/npc/data). Available on any `Entity`, not just `NpcEntity`. | Read-only reference, modify through its functions. |
| `npc.actions` | `NpcActionController` | Direct access to the NPC's action channels, see [Actions and Concurrency](/docs/hollowengine/scripting/npc/actions). | Read-only reference, modify through its functions. |

```kotlin
import ru.hollowhorizon.hollowengine.common.entities.setNameplate
import ru.hollowhorizon.hollowengine.common.attachments.components.NameplateMode

npc.setNameplate("Merchant", NameplateMode.SHOW)
```

## Common Minecraft API properties

| Property / method | Type | Purpose |
|-------------------|------|---------|
| `npc.uuid` | `UUID` | Unique entity id. |
| `npc.id` | `Int` | Runtime entity id in the world. |
| `npc.position()` | `Vec3` | Current position. |
| `npc.x`, `npc.y`, `npc.z` | `Double` | Entity coordinates. |
| `npc.health` | `Float` | Current health. |
| `npc.maxHealth` | `Float` | Maximum health. |
| `npc.isAlive` | `Boolean` | Whether the entity is alive. |
| `npc.isCustomNameVisible` | `Boolean` | Whether the name is visible above the entity. |
| `npc.customName` | `Component?` | Minecraft name component. |
| `npc.mainHandItem` | `ItemStack` | Item in the main hand. |
| `npc.offhandItem` | `ItemStack` | Item in the offhand. |
| `npc.target` | `LivingEntity?` | Mob target. |
| `npc.navigation` | `PathNavigation` | Pathfinding navigation. |

Example:

```kotlin
import net.minecraft.world.InteractionHand

npc.health = 10f
npc.isCustomNameVisible = true
npc.setItemInHand(InteractionHand.MAIN_HAND, item("minecraft:stick"))

val currentPos = npc.position()
val target = npc.target
```

## Components instead of old pseudo-properties

A component groups related entity settings. For example, `Model` selects the model, while `BodyComponent` controls collisions for its main body:

```kotlin
import ru.hollowhorizon.hollowengine.common.attachments.api.set
import ru.hollowhorizon.hollowengine.common.attachments.components.BodyComponent
import ru.hollowhorizon.hollowengine.common.attachments.components.BodyMode
import ru.hollowhorizon.hollowengine.common.attachments.components.Model

npc.set(Model("hollowengine:models/entity/player_model.gltf"))
npc.set(BodyComponent(mode = BodyMode.BLOCKING))
```

Set the animator in the selected model’s `.hemeta` using `animation-controller`. The built-in player model already refers to `hollowengine:standard_player`.

For animations, see [Animations](/docs/hollowengine/models/animations).

## Saving NPC references

Do not persist the `NpcEntity` object itself across reloads. Store its UUID:

```kotlin
val tag = stateTag()
tag.putUUID("guide", npc.uuid)
```

After loading, use `entityRef<NpcEntity>(uuid)` (the type parameter is required):

```kotlin
val guideRef = entityRef<NpcEntity>(tag.getUUID("guide"))
val guide = guideRef.resolve()
```

This is safer than keeping a direct entity reference because Minecraft can unload or recreate entities. `entityRef` waits until the body is loaded; to reach an NPC whose chunk is unloaded, use `npcs[uuid]` or its id instead, see [NPCs Outside the World](/docs/hollowengine/scripting/npc/registry).

## Name plates

Use the HollowEngine name-plate API instead of combining `customName` and `isCustomNameVisible` manually. It works with `NpcEntity` and other entities, is synchronized to clients, and is saved with the entity.

```kotlin
import ru.hollowhorizon.hollowengine.common.entities.nameplateMode
import ru.hollowhorizon.hollowengine.common.entities.setNameplate
import ru.hollowhorizon.hollowengine.common.attachments.components.NameplateMode

npc.setNameplate("Merchant", NameplateMode.SHOW_ON_HOVER)
npc.nameplateMode = NameplateMode.SHOW
npc.nameplateMode = NameplateMode.HIDDEN
```

`SHOW` uses normal Minecraft name rendering. `HIDDEN` suppresses the nameplate. `SHOW_ON_HOVER` shows it only while the player points at the entity.

`Entity.name` is Minecraft's display `Component` and remains read-only. `customName` is the low-level vanilla `Component?` used to replace that name. Use it when a formatted or translatable component is required. `setNameplate(text, mode)` is the normal scripting API: it assigns plain text and a visibility mode together. `nameplateMode` changes only the mode while keeping the current `customName`.
