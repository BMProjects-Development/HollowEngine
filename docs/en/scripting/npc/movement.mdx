<center><h1>Movement and Interaction</h1></center>

*Walking, looking, using blocks, and interacting with entities.*

It's recommended to read [Actions and Concurrency](/docs/hollowengine/scripting/npc/actions) first: every function here comes in a `suspend` form (waits for you) and a `startX` form (runs in the background and gives you a handle), and each one uses one of the `MOVEMENT`, `LOOK`, or `HANDS` channels.

## Moving to an entity or a position

```kotlin
npc move player                               // to an entity, default distance/speed
npc.move(player, dist = 2.0, speed = 1.2)     // to an entity, custom distance/speed
npc move pos(10, 64, 10)                      // to a position, default distance/speed
npc.move(pos(10, 64, 10), dist = 0.5)         // to a position, custom distance
```

`npc move player` and `npc.move(player)` are the same call, `move` is declared as a Kotlin `infix` function for the simple case, so the dot is optional. All of these are `suspend` functions: the script waits until the NPC arrives (or gives up). Every one of them also has a `startMove(...)` twin that returns immediately with an `NpcAction<MoveResult>` handle, exactly as described in [Actions and Concurrency](/docs/hollowengine/scripting/npc/actions).

```kotlin
val walking = npc.startMove(player) // does not wait
// ... do other things ...
val result = walking.await()
```

### What `move` gives you back

Movement functions return a `MoveResult`, so you can tell what actually happened instead of just assuming the NPC arrived:

| Value | Meaning |
|-------|---------|
| `MoveResult.Arrived` | The NPC reached the target distance. |
| `MoveResult.Unreachable` | No path could be found for a while (see `unreachable` below). |
| `MoveResult.TargetUnavailable` | The target entity disappeared, changed dimension, or its reference went stale (see `unavailableTarget` below). |

```kotlin
val result = npc.move(player)
if (result != MoveResult.Arrived) {
    npc.say("I can't reach you!")
}
```

:::advice
If you only care about "walk there, I don't need to check anything", you can keep ignoring the return value, exactly like in older scripts. Checking `MoveResult` is optional, it is there for when you want to react to a failed walk.
:::

### Fine-tuning movement with `MoveOptions`

For full control, pass a `MoveOptions` instead of `dist`/`speed`:

```kotlin
npc.move(
    player,
    MoveOptions(
        speed = 1.2,
        arrivalDistance = 2.0,
        unreachable = UnreachablePolicy.FAIL,
    ),
)
```

| Field | Default | Meaning |
|-------|---------|---------|
| `speed` | `1.0` | Pathfinding movement speed. |
| `arrivalDistance` | `1.5` | How close counts as "arrived". The NPC brakes to stop there. `0` walks it right onto the point, as close as it gets. |
| `facing` | `Facing.Path` | Which way the NPC faces while it walks; see [Which way the NPC faces](#which-way-the-npc-faces). |
| `passDistance` | `1.0` | How close a point the move passes through, rather than ends at, counts as passed; see [Walking through several points](#walking-through-several-points). |
| `avoid` | none | Zones this move keeps out of; see [Keeping out of zones](#keeping-out-of-zones). |
| `navigation` | none | Changes the NPC's [navigation settings](/docs/hollowengine/scripting/npc/navigation) for this move only. |
| `repathIntervalTicks` | `10` | How often the NPC recalculates its path while walking. |
| `targetMoveThreshold` | `1.0` | If a moving target (like a player) moves further than this since the last path, the NPC repaths immediately instead of waiting for the next interval. |
| `stuckTimeoutTicks` | `60` | If the NPC hasn't made progress for this many ticks, it is considered stuck and forces a repath. |
| `unreachableTimeoutTicks` | `40` | How long path-finding is allowed to keep failing before `unreachable` kicks in. |
| `unreachable` | `WAIT_AND_RETRY` | What to do when no path can be found (see below). |
| `unavailableTarget` | `WAIT_AND_RETRY` | What to do when the target entity is gone or invalid (see below). |

Both policies work the same way: `WAIT_AND_RETRY` keeps trying forever (useful for "just get there eventually" scripted scenes), while `FAIL` gives up and returns `MoveResult.Unreachable` / `MoveResult.TargetUnavailable` so your script can decide what to do next.

```kotlin
enum class UnreachablePolicy { WAIT_AND_RETRY, FAIL }
enum class UnavailableTargetPolicy { WAIT_AND_RETRY, FAIL }
```

How the NPC finds its way and walks it, its jumps, its speed on straights and in turns, the blocks it walks around, is set up per NPC by its [Navigation component](/docs/hollowengine/scripting/npc/navigation).

### Walking through several points

Give `move` a list of points and the NPC walks through them in turn without stopping at any but the last:

```kotlin
val route = listOf(pos(10, 64, 10), pos(20, 64, 10), pos(20, 64, 25))
npc.move(route)
npc.move(route, MoveOptions(passDistance = 2.0, arrivalDistance = 0.5))
```

A point before the last counts as passed once the NPC is within `passDistance` of it, and `arrivalDistance` is for the last one. The NPC plans its pace along the points still ahead, so it rounds a point like any other turn and brakes only for the last. To stand at a point for a while or look around there, use separate moves. `startMove(points)` is the background form.

The patrol component (`hollowengine:patrol_path`) walks its points the same way: through those it does not wait at, without stopping.

### Which way the NPC faces

By default the NPC faces the way it walks. `facing` keeps it facing something else, and it walks sideways or backward as it has to, slower by the [backward and sideways speeds](/docs/hollowengine/scripting/npc/navigation#movement) of its settings:

```kotlin
npc.move(pos(0, 64, 5), MoveOptions(facing = Facing.at(player)))   // backs away from the player, keeping an eye on them
npc.move(pos(0, 64, 5), MoveOptions(facing = Facing.at(pos(0, 64, 0))))
npc.move(pos(0, 64, 5), MoveOptions(facing = Facing.Yaw(90f)))
```

| Value | Faces |
|-------|-------|
| `Facing.Path` | the way it walks |
| `Facing.at(entity)` | the entity, for as long as it is there |
| `Facing.at(position)` | the position |
| `Facing.Yaw(degrees)` | a fixed direction, as vanilla counts yaw |

A short walk to a point behind the NPC is taken backward on its own, without `facing`: see **Step back** in its [settings](/docs/hollowengine/scripting/npc/navigation#movement). For a jump over a gap the NPC turns to face the landing, and turns back once it is down. When the move ends, the NPC turns the rest of the way to what it faced before it is done.

[`lookAt`](#looking-at-something) while the NPC walks works as `facing` too: the body turns to what it looks at and the NPC walks on sideways or backward. Whichever was asked for later wins, the look or the facing of the move, and once the look ends the facing of the move is back.

### Keeping out of zones

A `Zone` is a box or a sphere in the world. The NPC either never enters it or walks around it at a cost, in blocks of walking for every block of it it crosses; a block counts as in a zone when its middle is.

```kotlin
val yard = Zone.box(pos(0, 60, 0), pos(10, 70, 10))           // never enters
val flowers = Zone.sphere(pos(5, 64, 20), 3.0, cost = 6f)     // walks around if it is worth it

npc.move(pos(30, 64, 30), MoveOptions(avoid = listOf(yard, flowers)))   // for this move
npc.avoid(yard)                                                          // for every way it walks
npc.stopAvoiding(yard)
npc.stopAvoidingAll()
```

A zone given to `avoid(...)` holds for every way the NPC walks, its goals included, until a script lets it in again. It is not saved with the NPC: a script that needs it after a reload adds it again. An NPC that stands in a zone it may not enter walks out of it the shortest way and does not come back.

### Stopping

```kotlin
npc.stopMoving()
```

Cancels whatever the NPC is currently walking toward and stops its navigation immediately.

## Looking at something

```kotlin
npc.lookAt(pos(0, 64, 0))
npc.lookAt(player)
```

Smoothly turns the NPC's head and body toward a position or entity over about 1.5 seconds (this is the `suspend`, waiting form). While the NPC walks, it turns its body to what it looks at and walks on sideways or backward, see [Which way the NPC faces](#which-way-the-npc-faces). Use `startLookingAt(...)` for the background form, and `clearLookTarget()` to cancel it early:

```kotlin
npc.startLookingAt(player)  // does not wait
npc.clearLookTarget()       // cancel it
```

### Instant, per-tick turning: `lookAtNow`

`lookAtNow` is different from the rest of this page: it does **not** use the `LOOK` channel and does **not** wait or run in the background. It turns the NPC by a limited angle right now, once, and returns whether the NPC is already close enough to be considered "facing" the target:

```kotlin
val facing: Boolean = npc.lookAtNow(player, maxAngularSpeed = 360f)
```

There are two ways to use it: call it repeatedly (for example once per tick from an `onUpdate { ... }` handler in a [node script](/docs/hollowengine/scripting/node)) with a small `maxAngularSpeed` to make the NPC turn smoothly and keep tracking a moving target, or call it once with a large `maxAngularSpeed` to snap the NPC's facing instantly.

## Using a block

```kotlin
npc.useBlock(pos(10, 64, 10))
```

Walks the NPC to the block, turns to face it, and uses it with the main hand, useful for levers, buttons, and other interactive blocks. Only players can normally use blocks, so this goes through a fake player behind the scenes; a modded block that specifically checks for a real player may not respond to it. Extra parameters:

```kotlin
npc.useBlock(pos(10, 64, 10), hand = InteractionHand.OFF_HAND, reach = 4.0)
```

`useBlockNow(pos, ...)` does the same thing instantly, without walking or waiting, and only succeeds if the NPC is already within `reach`. `startUseBlock(...)` is the background form.

:::warning
`useBlock`, `destroyBlock`, and `interact` all walk the NPC to the target first, and that walk uses the same `MOVEMENT` channel as `move`/`startMove`. If the NPC was already walking somewhere in the background, that walk gets replaced, the same rule from [Actions and Concurrency](/docs/hollowengine/scripting/npc/actions) applies here too.
:::

## Destroying a block

```kotlin
npc.destroyBlock(pos(10, 64, 10))
```

Walks to the block, faces it, and breaks it as a fake player would (respecting tool requirements by default). Set `requireCorrectTool = false` to let the NPC break blocks it doesn't have the right tool for. `startDestroyBlock(...)` is the background form.

## Interacting with an entity

```kotlin
npc.interact(playerRef)
```

Walks to the target entity and interacts with it with the given hand (right-clicking it, essentially). `interactNow(target, ...)` does it instantly if already in range, without walking. `startInteract(...)` is the background form.

```kotlin
val result: InteractionResult = npc.interactNow(someEntity)
```
