<center><h1>Playing effects</h1></center>

*Start an effect from a command, a script, or a model bone, and steer it while it runs.*

The Kotlin examples below are server `.node.kts` fragments. `entity` is the entity the effect follows, `player` is a server player, and `level` is that player’s world (`player.serverLevel()`). Create the `.vfx` first using the [introduction](/docs/hollowengine/vfx).

## Effect names

An effect name is a resource id. `project:vfx/sparks.vfx` is the file `hollowengine/assets/project/vfx/sparks.vfx`; the short forms `project:sparks` and `project:vfx/sparks` mean the same. Effects from addons and resource packs use their own namespace. The command suggests every loaded effect.

If an effect does not play, check the name, reload client resources with `F3 + T`, and read the IDE console for a message about a file that could not be parsed.

## Commands

The `/he vfx` command accepts a position or an entity and an effect name:

```mcfunction
/he vfx ~ ~1 ~ project:sparks
/he vfx @s project:sparks
```

A position plays the effect at that point. An entity plays it on the entity and it follows the entity for as long as it lives.

## From Kotlin

Use `Vfx.play(level, position, "project:sparks")` or `Vfx.play(entity, "project:sparks")`. Both return a `VfxHandle`:

```kotlin
import ru.hollowhorizon.hollowengine.common.vfx.Vfx

val handle = Vfx.play(level, player.position(), "project:sparks")

handle.moveTo(player.position().add(0.0, 2.0, 0.0))   // point-anchored effects only
handle.stop()                                          // stop emitting, let particles finish
handle.stop(immediate = true)                          // clear everything at once
```

Entity-anchored effects follow their entity automatically, so `moveTo` has no effect on them. The effect is played for everyone who can see it: everyone in the dimension for a point, and everyone tracking the entity for an entity. A player who starts tracking the entity later receives the effect from `handle.update()`.

## Passing data to an effect

Use `handle.jumpTo("release")` to move to a named timeline event and continue from there. VFX [section rules](/docs/hollowengine/ide/timeline) are evaluated on the clients playing the effect; keep server gameplay logic independent of what a client displays.

Every handle has a data store that effect expressions read as `d.<name>`. Write to it with a `dataKey`, the same typed key used for [NPC data](/docs/hollowengine/scripting/npc/data):

```kotlin
val Charge = dataKey<Float>("charge") { 0f }

val handle = Vfx.play(entity, "project:beam")

handle[Charge] = 0.25f       // the effect sees d.charge == 0.25
handle[Charge] = 1f          // and updates as soon as the value changes
```

In the effect, use the name from the key: `d.charge * 4`. A value that was never written reads as `0`. This is how one effect can be reused for a weak and a strong version of the same attack, or driven by gameplay such as a charge meter.

## On a model bone

An effect can be a bone attachment of a model. Open the model in the [Rig Editor](/docs/hollowengine/models/rig-editor), select a bone, and use **+ Attach** to add a VFX attachment:

| Field | Meaning |
| --- | --- |
| **Effect** | The `.vfx` file to play. |
| **Offset**, **Rotation**, **Scale** | Placement relative to the bone. |
| **Start with the model** | Begin when the model appears; otherwise a script starts it. |

The effect follows the bone as the model animates, which makes it the way to put a flame on a sword or a glow on a hand.

## Tips

- Keep one effect per idea and combine them in scripts, rather than one giant effect with every variant.
- Use **Limit** on emitters and a **Duration** on the effect so nothing runs forever by accident, and stop long-lived effects with `handle.stop()` when their owner is gone.
- Test with a shader pack if your players use one. Effects are drawn on top of the pack's final image, but fog and weather still come from the pack.
